# Rivloom 0.1.29

正式发布与验收已完成，产物、安装、公开下载及未覆盖项见[0.1.29 发行验收](0.1.29-verification.md)。

## 任务续接与停止

- 停止按钮直接位于输入区；已有输入保留为草稿。停止尚未确认时继续等待真实回执，不提前启动下一轮。
- 新发生的规划或执行失败保留历史结果，并继续处理已排队的下一条消息。人工暂停和上下文准备失败仍明确提示。
- 在上一轮已安全结束后发送新消息，会直接开启下一轮，包括已停止的会话；重复请求不会撤销后来的暂停或停止操作。
- 修复序号为零的远端邀请已确认取消后仍无法收尾，以及旧投递失败覆盖新取消消息投递状态的问题。既有远端停止未确认记录不会因升级被强制解锁。

## 设备选择与结果

- 由模型结合任务语义选择设备；“本机”按提交设备身份解释，调度遵守明确的目标约束，不再依赖固定句式匹配。
- 规划设备与实际执行设备分别展示；停止或失败后仍保留已观测到的归属，没有执行记录时不猜测设备。
- 完成结果缺少空附件列表时可正常解析，非法附件仍拒绝，不修改已保存的旧失败结果。

## 会话界面

- 精简执行状态、诊断和结果区域，完成后优先展示结果，复制与引用使用图标按钮。
- 调整正文排版、引用箭头和输入区；思考等级使用支持键盘的自定义菜单，移除重复焦点边框。
- 侧栏设备名称旁提供独立编辑按钮；模型速率只保留箭头、数值和单位，并在可用空间居中，统计范围仍限本机。

## 平台与升级

Windows x64 沿用桌面安装器和签名更新频道；Linux x64 同步任务调度、续接和停止修复，继续手动停止节点、更换程序并保留数据目录。ARM64 暂不发布。

固定核心保持 `1.18.31-rivloom.9b07cf442a7e`，SDK/plugin `1.18.31`，Node.js `24.19.0`。新增消息暂停原因是可选的本地状态；旧记录信息不足时保持保守处理，不自动重试历史失败任务。Windows 发布者签名和完整跨版本升级矩阵仍未覆盖。
