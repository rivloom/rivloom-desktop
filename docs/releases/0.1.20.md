# Rivloom 0.1.20

## 上下文与项目记忆

会话新增上下文查看界面，可以检查当前要求、带来源的约束和决定、模型推断、已处理的历史与知识读取，以及 Runtime 的规则恢复和压缩准备记录。用户可确认、修订或撤回条目；来源版本和修改历史保留，模型推断不会自动成为用户授权。

已确认的条目可由用户明确保存为项目记忆，供同项目后续会话按需读取。替代记忆需要核对当前版本，撤回后拒绝新的读取；已经送入执行中的内容无法撤回。项目记忆与会话记录分别管理，删除会话不会自动删除其已保存的项目记忆。

Wiki、Skill 与历史按需读取联通，每页最多 **32 KiB 的 UTF-8 JSON**，包含正文、元数据和转义。通过返回的 `nextOffset` 继续读取固定版本；页边界保留完整 Unicode 字符。项目范围、Brain 分享、执行身份和撤回状态仍需逐页验证，历史读取授权不等于另一节点的私人知识库访问权。

## 续聊与节点交接

普通会话等待补充或中断后，发送新要求会先确认原执行已停止，再继续同一任务和 Runtime 会话。重试同一次提交复用请求标识和正文，避免重复创建消息。修复知识工具已完成后仍阻止工作流交接的问题，保留活动工具和未知工具的停止检查。

Windows 引擎退出时，各检查步骤共享原有总时间预算，让较慢的进程快照查询使用后续步骤的空余时间；整体等待上限、进程归属及退出证明要求保持。超时或无法确认停止时，仍报告失败。

本轮以新建合成资料完成三台 Windows 设备的历史/Wiki 分页与连续交接；本机普通会话完成等待中续聊、同请求重放，以及退出重开后的同会话恢复。真实模型的两次压缩保留了受测目标、约束和内容，但一次摘要遗漏了末页已读状态，导致该页重读一次。上下文记录和来源可追溯，不保证模型始终正确理解或不再重复读取。

## 历史存储维护

沿用回收站三个月保留规则，永久删除会话时记录清理进度，并通过固定 Runtime 的会话接口删除可确认归属的历史及子会话；随后核对删除结果。正在使用、被其他保留任务引用或归属不明的会话暂缓清理，失败可在重启后或手动重试。维护不调用模型，不扫描或删除用户项目原文件，不自动压缩 SQLite 数据库文件。

## 运行环境与升级

Windows x64 和 Linux x64 继续使用固定源码构建的 OpenCode **1.18.31-rivloom.9b07cf442a7e**，核心固定 **9b07cf4**；SDK/plugin **1.18.31**，Node.js **24.19.0**。ARM64 暂不发布。Windows 应用内更新沿用既有签名公钥，Authenticode 代码签名尚未配置。Linux 使用手动升级，详见[Linux 0.1.20 说明](linux-0.1.20.md)。

0.1.19 与本版的隔离混合节点验证覆盖历史互通；旧执行节点不能完整读取新版长 Wiki，需升级参与执行的节点。32 KiB 是单次读取预算，不是模型窗口、总存储容量或用户输入上限。操作系统重启、断电及压缩生成过程中崩溃未纳入本轮验收；远端原始 Runtime 数据库清理也未做实体核验。

下载与各平台实际发布状态见[官网](https://rivloom.com/download/)，使用说明见[随包说明](../../DESKTOP-README.md)，设计边界见[ADR 0016](../adr/0016-context-memory-and-runtime-retention.md)。
