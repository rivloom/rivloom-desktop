# Rivloom 0.1.30

发行准备中。Windows/Linux x64 将采用同一套固定的 OpenCode 1.18.33 核心；正式安装包、公开下载、签名更新、官网与 R2 检查仍须按本次源码完成。

## 执行核心

- 固定核心更新为 `1.18.33-rivloom.655285f835f8`，SDK/plugin 同步至 `1.18.33`，Node.js 保持 `24.19.0`。
- 纳入上游上下文压缩与消息重放、模型变体及部分提供方请求处理修复；实际提供方行为仍取决于所用模型与账号配置。
- 保留 Rivloom 的权限、任务停止、会话历史、知识工具和节点协议边界；不会自动重试或改写已有失败任务。

## 来源与完整性

Windows 和 Linux 均绑定完整的 6,662 个源码输入、固定构建工具与依赖锁。Windows schema 2 新增完整生产者清单，并独立核对消费端 smoke、实际二进制、构建记录及导入来源；未经批准的外部产物继续拒绝。

Windows 从源码准备核心时，将 Git 符号链接保存为其原始目标文本，避免 runner 将目标中的路径分隔符转换后造成完整清单不一致。完整摘要和文件完整性门槛保持不变。

## 平台与升级

Windows x64 沿用正式桌面安装器及原公钥签名更新频道。Linux x64 继续手动停止节点、更换程序并保留数据目录，最低 glibc 保持 `2.30`。ARM64 暂不发布。

应用内更新签名与 Windows 发布者签名是不同的机制；Authenticode 和完整跨版本升级矩阵仍未覆盖。本次没有新增真实提供方 OAuth/付费模型、原生窗口视觉或实体多机验收，不将合成测试结果描述为这些场景通过。
