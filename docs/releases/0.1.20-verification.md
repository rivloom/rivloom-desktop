## 功能验收范围与限制

本机原生界面使用新建合成资料验证会话条目确认、项目记忆替代与撤回，以及新会话按需读取；三台已配对 Windows 设备共同验证历史/Wiki 分页、撤销授权及连续交接。本机普通会话覆盖等待输入、同请求重放、冲突正文拒绝，以及用户退出重开后的原会话续聊；远端实机覆盖工作流续聊，没有把普通任务分支写成三机均已覆盖。

两次真实模型压缩保留了受测目标、约束和来源内容；第二次摘要遗漏末页已读状态，产生一次重读。来源与处理记录可追溯，不保证模型完美回忆、理解正确或零重读。隔离 Runtime 清理测试覆盖记录删除、账号隔离及持久重试；实机只删除可丢弃测试会话，没有核验远端原始 Runtime 数据库。旧 0.1.19 节点的历史互通与长 Wiki 不支持分支已验证，参与新版知识分页的执行节点需要升级。操作系统重启、断电和压缩摘要生成中崩溃仍按约定暂缓。详见 [ADR 0016](../adr/0016-context-memory-and-runtime-retention.md)。

## 此前失败与必要修复

早期 0.1.20 候选曾被 Windows 停止阶段的固定子预算阻止。最终源码让首次归属进程快照使用共享 5800 ms 截止时间内的剩余预算；整体截止、后续阶段上限、身份归属和真实退出证明保持，超时仍失败。

另一次 session-crash 检查在服务主进程已退出、所属 Runtime 可能仍在退出时读取 SQLite，暴露检查器的竞态窗口。最终检查器先固定所属进程身份，要求服务正常退出、服务与 Runtime 监听关闭且已记录进程树退出，再执行原有数据库断言；有界等待覆盖晚退、不退和非零退出。没有吞掉数据库错误、删除 WAL 或修改产品停机来通过检查。旧 CI 未保存 SQLite IOERR 子码，因此不把该竞态分析写成已证实的数据库损坏根因。失败记录保留，本页成功状态只来自上表最终源码。
