## 使用方式

从左侧设置区打开 **技能与记忆**。只有本机工作区创建者可以管理登记、说明和分享范围。

### Skills

1. 在“我的 Node”添加直接包含 `SKILL.md` 的文件夹。文件头需要 `name` 和 `description`；脚本、参考资料和其他支持文件保留在原文件夹。
2. 新登记的 Skill 仅本机可见。打开“管理分享”，选择允许读取它的 Brain。
3. 本机列表显示“仅本机可见”或具体分享给哪些 Brain。更新原文件后可以刷新列表；取用内容时也会自动核对来源最新版。
4. 切换到某个 Brain，可以搜索本机及其他成员向该 Brain 分享的条目。Agent 使用同一目录判断是否需要某项能力。

例如 A 与 Brain 配对、B 与 Brain 配对，即可 A → Brain → B 发现及取用；不需要 A 与 B 直接配对。Brain 也可以在自己的任务中取用 B 的 Skill。

目录只传名称、用途摘要、分类、来源和版本。Agent 先搜索，再读取 `SKILL.md` 和文件清单，最后逐个获取需要的支持文件。指定 `materialize=true` 时只把该文件写入当前任务的 `.rivloom-knowledge/` 目录。随后由普通引擎工具执行，沿用当前任务审批模式；登记、读取和分享本身均不运行脚本。

每个任务首次读取时固定版本。后续读取若发现来源已变，不会混用两个版本，需要新任务重新获取。新任务读取来源当前版，不会静默退回旧缓存。撤销分享阻止后续取用；已经交付给其他设备的字节无法远程收回。

### Wiki 记忆

用户确认的默认规则是：**默认本机，手动分享给 Brain**。

记忆由名称、用途摘要、分类路径、正文及适用范围组成。示例：

```text
人物/
  张三/
    信息
    工作
项目/
  网站/
    决定
    规范
```

分类可以任意分层；先展示摘要，正文按条目读取。正文应写已知事实和来源，不推断未提供的个人情况，不保存密钥。可以限定某个工作目录，或设为本机所有目录。正常任务可以保存有来源的事实；只读规划不能写入。审批模式为“询问”时，写入走官方引擎审批，拒绝不会保存。

本机可以编辑条目并查看历史版本。编辑带版本核对，旧编辑窗口不能覆盖新内容。已有分享范围在编辑后保留，其他设备之后读到的是更新后的内容。

“分享此分类中的条目”批量设置**当前分类及筛选条件下显示的现有条目**，一次操作全部成功或全部失败。它不是自动分享规则，新建条目仍默认私有。移除记忆会删除该条目和其历史，界面先展示确认；移除 Skill 登记不会删除原文件夹。

### 本机与工作目录说明

- 本机主说明：应用数据目录中的 `knowledge/AGENTS.md`，只进入本机创建者发起的任务。
- 工作目录说明：对应目录的 `AGENTS.md`；不存在时支持 `agent.md`。编辑入口会显示实际文件路径。
- 后续执行开始时读取说明；Wiki 正文不会整库注入。远端任务不能通过知识库工具读取本机私有条目或本机主说明，只能读取向对应 Brain 分享的内容及其执行目录说明。
- 已有 Node 身份时，即使关闭网络发现，本机记忆和说明仍可管理。

## 整理机制的当前范围

应用启动和记忆变更后，以约 60 秒合并触发一次整理，也可手动点击“整理记忆”。它生成分类索引 `knowledge/wiki/INDEX.md`，标出同一适用范围中正文完全相同的条目，保留原文、冲突事实和历史。

当前的语义分类由用户或执行任务中的 Agent 通过记忆工具完成。后台整理不额外调用模型，**尚不包含独立的 AI 定时重写、相似记忆合并或自动推断人物档案**。这部分若后续需要，另行确定触发条件、审阅方式与模型额度授权。

## 运行边界

- 共享来源必须在线且仍有授权；离线或旧版 Node 不提供可验证的最新版，会显示来源不可用。
- 共享不会跨 Brain 自动转发。Brain 不替来源 Node 自动扩大分享范围。
- 只扫描用户登记的 Skill 文件夹，不自动扫描个人 Skill 目录。拒绝链接、目录穿越、特殊文件与常见凭据文件名。
- 目录最多 2,000 项，Agent 每页 20 项；Skill 最多 128 个文件、每文件 2 MiB、总计 16 MiB。Wiki 正文上限 32,000 字符，说明上限 24,000 字符。
- 不保证另一台 Node 的脚本依赖或操作系统恰好相同。Agent 应阅读说明，在实际执行位置选择已有工具；知识库读取不会安装依赖。

## 实现与验证入口

持久化在 `knowledge/library.sqlite`，任务版本记录在 `knowledge/tool-state.sqlite`。官方 OpenCode 仍为 1.18.25，通过三个受控工具 `rivloom_knowledge_search`、`rivloom_knowledge_read`、`rivloom_memory_save` 接入，不替换官方 Agent 循环。

官方插件包与桌面依赖一起锁定。首次引擎启动从本地运行时准备依赖，解决 OpenCode 本地插件也等待安装 SDK 的问题；不是用户 Skill 的自动安装器。新增依赖许可来源记录在 `dependency-licenses.json`，包括生成类型包的发布许可声明和 Kubernetes 上游 Apache 2.0 原文。

```powershell
npm run test:knowledge      # 三个真实隔离 Node + 官方引擎 + 本地模拟模型
npm run preview:knowledge   # 生产 UI + 真实知识库 API + 合成节点，不启动模型
```

预览输出回环地址，数据放在 `.data/knowledge-ui/`，不会打开安装版用户数据。完整结果见维护者本地验证记录；设计决策见 [ADR 0010](adr/0010-shared-skills-memory.md)。
