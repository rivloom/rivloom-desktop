# 失败步骤重试与远端成果

2026-09-11 本地开发完成，随 0.1.13 提交发行；公开状态以 [VERIFICATION](VERIFICATION.md) 顶部的发布证据为准。与本轮较早的 [简洁输入框](COMPOSER.md) 改动一起保留；测试使用独立目录、回环合成模型和浏览器夹具，没有操作用户安装版、真实项目或真实模型。

## 失败步骤重试

当前轮结束为失败时，失败业务步骤旁提供“重试此步骤”。恢复所选步骤及尚未执行的受阻后续步骤，已完成的前置或并行分支、旧执行记录和文件全部保留；另一个失败分支仍保持失败。消息队列保持原暂停状态，不因重试自动执行下一条消息。

重试前重新读取官方引擎 session 状态和工具记录，确认旧执行及支持检查的外部工作已结束。未知执行、未确认的后台操作、离线或尚不支持新能力的远端节点不会被当作可安全重跑。没有开始执行的材料准备失败也可重新尝试。当前限制为每步最多 16 次执行及 16 次明确重试。

`POST /api/workflows/:id/steps/retry` 绑定版本、轮次 requestID、stepID、原 attempt 数和请求 UUID。版本变化/新轮次竞争会拒绝旧请求；重试回执随步骤持久化，重复请求不会额外派发。历史轮次不提供重试按钮。原“重新规划”行为独立保留。

## 远端成果按需取回

双方支持 `workflow-controls-v1` 时，新远端工作流执行使用持久化的 `resultDelivery: on-demand`。源设备完成经过路径验证和哈希检查的成果快照后，发起端即可显示完成、回答、文件描述和来源，不再等待文件内容到达本机。

文件区显示机器、相对路径、大小和“保留在远端”。点击“取回到本机”只请求所选文件，沿用现有分块、完整性校验和断线续传。取回后启用本机预览、打开、定位和另存为。离线请求显示错误并保留重试入口；校验失败的缓存只有在原任务路由、来源与描述一致的明确重试下才会清空并重新校验。

同一计划的后续步骤需要前置成果时，编排器会先取回并验证必需材料，再派发；当前中转仍经过协调端。后续会话的规划或普通回答只读取包含来源与路径的会话记录，不因为继承远端成果描述而自动下载全部文件。需要跨设备读取历史文件内容时，通过现有资源查询与 `resources` 流程获取。

源端只接受原受信发起方、原 execution/digest 及已验证 manifest 内的 fileID，不能通过模型返回的任意路径读取文件。传输策略随元数据与 attempt 保存，重放不能降级。新增两项认证通道操作 `execution-files`、`execution-retry-check`；hello 仍保持旧解码器的 12 项能力上限，用新功能能力替换无协议作用的描述性 `executor` 标志。

兼容边界：旧节点或已经创建的旧 attempt 保留原自动回传规则；新行为需要两端升级后创建新的执行。原 Task/Brain 文件流程不变。

## 结果展示

回答使用独立的 Markdown 正文区域，标题、列表、表格和代码保留语义，代码/表格在内容区内滚动。交付文件集中成独立区域，多步骤文件按步骤区分；执行过程默认折叠。失败或停止时直接显示已经完成的部分。

普通消息底部间距从 30px 减为 18px，轮次间距从 32px 减为 16px；压缩进度标题、过程面板和用户气泡的空白，正文保留 1.65 行高。复制、选择、双语切换及此前已完成的单行输入工具栏继续保留。

## 验证

- 逻辑回归 380/380、协议 13/13，均零跳过；生产构建、TypeScript、双语覆盖、版本一致性与测试分类审计通过。
- 官方 OpenCode + 两个隔离服务 + 回环合成模型：本机/远端失败步骤重试、保留前置结果、未取回即完成、双文件只取一份、依赖文件中转及原审批/并行/转交/连续会话/重启回归通过。
- 追加独立服务检查确认远端文件状态跨重启保存、源端离线取回可重试、重连后继续，以及后续轮次只用结果记录时零成果下载。
- 结果 UI 5 组与输入框回归 13 组通过，包含远端/接收中/失败/完成、单步重试请求、局部结果、多轮、Markdown、英文窄窗；截图逐张检查，零浏览器运行时错误。
