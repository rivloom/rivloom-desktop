# 待办、连接诊断与任务文件

本页说明 2026-09-06 开发的协作增强。源码和隔离工程检查已完成，正式安装、真实模型与双物理机统一验收待进行。这些新增功能尚未发布到现有官网下载包。

## 待办与提醒

侧栏「待办中心」集中显示当前操作者需要处理的审批、回答、验收、中断和失败。点击卡片回到原会话；完成事件可触发通知，不长期占据待办列表。相同请求不会因状态轮询反复提醒，旧的失败 Execution 不覆盖当前重试。

可以关闭桌面通知，或开启一小时免打扰。偏好和去重记录按本机用户保存，重启、随机端口变化不会重置。Windows 安装版在应用运行时发送仅含状态的系统通知，点击聚焦应用并进入任务；系统设置仍可能阻止显示。关闭应用后不会继续驻留提醒。

## 连接诊断

侧栏「连接诊断」可以检查本机或指定 Node 的发现、验证、互信、加密通道、协议能力、执行设置和资源新鲜度。离线节点缺失的信息显示未知，最近通信时间仅使用本次启动实际收到的验证消息。

「刷新并重试」重新触发已有发现与连接恢复，不删除身份、配对或任务，也不修改 Windows 防火墙。连续操作有五秒间隔。节点在线不表示任务已经运行；任务准入、人工等待和完成仍以原会话为准。

「复制摘要」只包含有限状态，不包含名称、任务正文、文件路径、网络地址、Node ID 或凭据。剪贴板不可用时，可在页面选择摘要手动复制。

## 输入附件与成果

1. 新会话点击「添加附件」，明确选择需要提供的文件。等待每项显示「已备妥」后发送；失败时可重试原文件或移除。单个文件最多 20 MiB，每批最多 10 个、合计 50 MiB。
2. 本机、指定 Node 和自动 Brain 路由均保留附件清单。对端通过加密通道分块接收，输入全部校验完成后才准入执行。附件落在所选项目的 `.rivloom-inputs/<任务 ID>/<文件 ID>/` 下，原 OpenCode 会话获得相对路径。仅传送用户选择的文件，不同步整个目录。
3. 会话内的「任务文件」显示本机接收状态与对方确认的发送进度。断线或接收端重启后按已保存进度续传；未确认的加密回执会先触发通道恢复，不创建另一项 Task 或 session。
4. 执行人可在任务进入待验收、已验收、已停止或失败后，点击「选择成果文件」，再点击「发布所选成果」。程序不扫描项目、不根据差异自动挑文件。直连成果回到原发起端；Brain 成果经原 Master 回到提交端，并校验当前 Execution 归属。
5. Windows 点击保存后选择新文件名；服务端再次核对完整性并拒绝覆盖已有文件。浏览器调试版通过受任务权限保护的下载链接保存。接收或下载文件不等于验收任务，也不会自动执行、解压或打开内容。

文件能力使用 `task-files-v1` 协商。旧节点的文字任务仍兼容，文件任务需升级参与节点；撤信或原任务终止会停止后续传输。敏感凭据名称、路径跳转、保留名称、图片格式与扩展名不一致等输入会被拒绝。

## 当前边界与统一真机检查

缓存总配额为 512 MiB、最多 4096 个文件记录，输入与成果各自最多 10 个、合计 50 MiB。已绑定文件作为任务历史保留，当前没有历史缓存清理界面；配额达到上限后拒绝新增。未发送草稿可在当前页面移除；草稿的本地 File 选择不会跨应用退出恢复，已经提交任务的节点传输进度会持久保存。

输入失败保持在原任务等待，不自动换文件、启动或改派；哈希损坏需检查原文件和接收端原因。此版本不追加已提交任务的输入清单、不做项目同步、离线首次投递、自动成果收集或自动任务拆解。

统一真机验收应覆盖 Windows 系统通知显示与点击、原生保存选择器、真实模型读取文字及图片、两台物理机文件往返、忙碌排队中的附件等待、断网与重启续传、撤信，以及正式数据升级保留。已有纯 mDNS 问题继续单列，隔离服务成功不替代这些检查。

实现决定见 [ADR-0007](adr/0007-attention-diagnostics-and-task-files.md)，工程检查状态见 [验证记录](VERIFICATION.md)。
