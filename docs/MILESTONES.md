## 当前工作顺序

1. 使用用户已创建的 DeepSeek Key 完成 M1 真实验证。Key 只在 Rivloom 客户端本机输入，不发到聊天、仓库、截图或报告。
2. 回到 M3.3，先对齐具体交互和完成条件，再继续跨节点人工介入、结果与验收能力。
3. M2 的正式发行完善暂缓，不因现有安装包而宣称商业发行已经完成。
4. M3.4 不沿用未经确认的“每个节点一个 Brain”或“Brain A 委派给 Brain B”等假设。双方讨论清楚 Brain、节点和任务的关系后再更新 ADR 与实施计划。

## M1 真实验证完成条件

1. 用户在本机“模型与额度”页面保存 DeepSeek Key，界面不回显完整 Key。
2. 经用户主动确认，发送一次固定、无项目文件、禁用工具的真实连接测试；它可能消耗 API 额度，不自动重试。
3. 确认 OpenCode 返回可用的 DeepSeek 模型，并把选定模型用于独立 Git fixture 中的固定编程任务。
4. 验证流式输出、编辑/命令审批、测试、代码差异、停止或失败提示以及最终验收。
5. 报告只记录模型标识、时间、结果和必要错误分类，不记录 Key、完整回复或用户项目内容。

## M3.3 当前已知事实

- 可信节点之间已经可以发送加密协作任务。
- 执行节点已支持自动、有限和每项确认三种本机调用策略，并能启动真实 OpenCode。
- 发起端已经能收到有序执行状态和最终摘要。
- 跨设备的角色、审批、追问、补充、停止、差异、产物和验收仍未完成。
- 当前“单个可复用项目和模型”的实现是已验证的第一切片，不自动视为 M3.3 的最终产品形态。

## 暂停项

- 不继续实现 M3.4。
- 不用旧的 30 分钟准备租约流程。
- 不优先开发 ChatGPT 登录、更多模型供应商、自动更新或正式发行签名。
- 不把自动化双实例测试描述成两位真人已经完成跨设备协作验收。
