## 厂商账号

在“账号登录”或“API Key”中查找厂商，确认工作区会使用此账号额度，然后按所选方式接入。

OAuth 目录直接读取打包的官方 OpenCode 1.18.25。隔离探测已确认 ChatGPT、GitHub Copilot 等入口；按引擎返回显示浏览器、设备码/授权码及必要的企业实例选项。不为没有 OAuth 的厂商虚构登录按钮。要求额外专用 API 参数的厂商暂不显示普通 Key 按钮，可选兼容接口自定义接入。模型目录代表引擎可配置模型，具体账号的权限、余额及模型可用性以厂商实际响应为准。

点击“登录”及厂商名称组成的按钮后，使用“打开厂商授权页”进入系统浏览器。按页面提供的说明完成厂商授权，回到 Rivloom 点击“已完成授权，连接”；需要返回授权码的方式会显示输入框。浏览器无法打开时，可复制授权链接。登录等待限时 10 分钟，可以取消；确认授权成功后的短暂保存阶段会锁定取消按钮。

接入流程不调用模型。真实连接测试必须单独点击并确认额度使用，沿用无工具权限、60 秒等待和 10 分钟最多 3 次的限制。连接成功只证明本次响应成功，不代表任意业务任务都适合该模型。

## 自定义 Provider

点击“自定义服务”，填写：

| 字段 | 用法 |
| --- | --- |
| 显示名称、Provider ID | ID 使用小写字母、数字、短横线，保存后固定，不能占用内置厂商 ID |
| API 地址 | 完整基础地址，例如 `https://api.example.com/v1`，或本机兼容服务 `http://localhost:1234/v1` |
| 接口协议 | Chat Completions 或 Responses，与服务商支持的接口一致 |
| 模型 ID | 每行一个，保留服务商要求的完整 ID，包括其中的 `/`；可写 `ID | 显示名称` |
| API Key | 需要认证的服务填写；编辑时留空保留原 Key。免认证服务勾选“不需要 API Key” |
| 可选容量 | 默认上下文 32768、输出 4096 Token；小容量本地模型可按实际限制调整 |

保存后点击对应已接入标签可修改，点击“添加另一个服务”可继续添加。移除模型会同步更新选择器；移除整个自定义 Provider 会删除其受管定义和凭据，并重置已失效的默认模型。内置厂商移除的是认证信息，引擎自带的免认证模型可能继续可用。

本轮没有增加温度、任意请求头、路由优先级、任意 SDK 包或逐模型复杂参数。基础地址不接受 URL 中嵌入的密码、查询参数、片段和配置变量；Key 单独保存。

## 认证、存储与运行边界

- 只有工作区创建者可修改接入、完成/取消 OAuth 或执行测试；成员只能查看可用模型。运行、等待人工介入或执行中断的任务存在时，接入配置被锁定。OAuth 进行期间也会阻止启动任务。
- 普通 API Key 通过官方 Auth API 写入本机独立引擎的 `engine/data/opencode/auth.json`，不会进入 Rivloom 业务数据库、接口响应或操作日志。自定义地址和模型保存在不含 Key 的 `engine/rivloom-providers.json`，通过官方 `OPENCODE_CONFIG` 加载；不覆盖已有主配置或项目配置。
- OAuth 在 `oauth-staging/<随机 ID>` 下的临时官方引擎中完成。只在当前授权仍有效且成功时，将认证结果交给主引擎的 Auth API；取消和迟到回调不能替换主引擎原凭据。正常结束确认临时进程树退出后清理其目录。异常退出不自动恢复登录或导入遗留凭据；清理未确认会要求重启。
- 厂商登录页由系统浏览器显示。Rivloom 不收集厂商密码，厂商 Token 的后续刷新继续由官方引擎负责。

## 验收与验证

运行 `npm run preview:models`，进入“设备与模型”查看合成预览。该预览的登录、保存均仅改变内存中的演示数据，不连接厂商、不执行模型、不保留 Key；不要填真实凭据。完整实现的真实厂商登录留待用户在自己的开发/候选版本中手动完成。

已验证：自定义 Chat Completions 和 Responses 请求由官方引擎发向本机模拟服务；精确模型 ID、Bearer 认证、免 Key、编辑后移除旧模型、保留空白替换 Key、重启持久化、删除与默认回退；原有 DeepSeek 操作及权限门禁仍通过。OAuth 生命周期用合成 Driver 验证，另用真实官方引擎验证暂存隔离与进程清理，未登录真实厂商、未消耗真实额度。中文/英文/390px 界面、原会话搜索回归通过。详见维护者本地验证记录。
