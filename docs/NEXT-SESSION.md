## 3. 连续会话的关键约定

- 执行中追加的新要求进入同一会话队列。当前轮成功结束且全部执行确认结束后，按发送顺序自动开始下一轮；停止或失败暂停队列，等待明确继续。模型提出的问题在当前轮直接回答，不变成下一条排队消息。
- 会话 ID、偏好和历史入口保持稳定。已结束轮次保留完整要求、完成条件、回答、结果与文件；下一轮重新规划，通过完整 JSON 会话记录及成果继续。不是无限复用一个引擎 session。
- 最多 50 条待执行消息，每条 12,000 字符和 5 个附件。每步材料最多 10 个、合计 1000 MiB，会话记录文件也计入；超限明确暂停，不能静默丢弃上下文。
- 草稿只有收到发送成功确认后才清空；重复请求复用原 requestID。完成上传的附件可恢复；未完成上传须提示重新选择。永久删除与过期客户端重放不能复活已删除会话或草稿。
- 历史清理、通知去重、队列暂停/取消和更新阻塞都要覆盖归档轮次与待执行消息。旧普通 Task/Brain 记录继续沿用原规则，新会话统一走工作流。
- Markdown HTML 不执行，远程图片不自动加载；预览继续检查上传者/任务成员权限。文本上限 256 KiB，图片预览上限 20 MiB，媒体编码支持由 WebView 决定。
