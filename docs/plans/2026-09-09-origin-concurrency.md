# 本机与远端任务分别控制并发

用户确认：本机自己发起的任务不设固定并发上限；其他机器发来的任务使用单独的并发额度，默认 3，可在 1–10 间修改。界面需要直接显示已保存值和明确的修改入口。

## 调度与数据

- 按持久任务来源区分本机、远端；同一远端执行的 Task、队列预留和接收记录只计一次，未确认执行继续占用原名额。
- 本机执行不消耗远端名额；解除全局单槽和同项目单任务限制，保留同一 Task 的串行控制、会话身份及停止确认。
- 每种来源分别遵循队列次序，远端名额已满不能堵住本机候选；队列暂停、附件、模型与信任条件继续生效。
- `maxConcurrent` 明确定义为远端并发额度。配置升为版本 3；旧版本固定的 1 自动迁移到默认 3，已有审批模式、开放状态、目录和模型保留。
- 独立保存并发的接口只改变并发值；旧客户端保存其他执行设置时不覆盖新的并发值。范围和整数在服务端验证，写盘成功后才更新内存。
- 下调额度不终止或撤销已有执行/预留；新增远端执行等名额空出，上调后派发等待项。
- Worker 的可用执行能力反映远端额度；新增能力协商后的来源统计展示本机、远端占用及远端上限。旧客户端仍收到可理解的基础负载结构。

## 界面

- 并发设置分别显示“本机任务：不设固定上限”和“其他机器任务：当前 n 项”。提供 1–10 选择器与明确保存按钮，区分已保存值和未保存修改。
- 队列面板展示当前两类并发设置并可直接打开修改窗口；模型与执行页提供同一设置，Brain 页显示上限与空闲名额的区别。
- 保留 10 项积压提醒，文案明确它与可修改的远端并发额度不同。
- 保持此前工作目录直接展示、队列入口去重、回复结果优先和跨机并行修复。
