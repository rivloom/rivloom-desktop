# 0.1.7 更新安装交接修复

用户报告：0.1.5 → 0.1.6 下载成功，在“确认任务状态并备份应用数据”停留，点击应用内更新弹窗的 X 后才继续安装。已确认是应用内弹窗。现有安装命令横跨停机、备份和安装器调用，前端持续打开 HTML 模态对话框；两个轮询源并行请求状态，备份没有独立进度。尚不能把用户现场的等待归因于某个 Windows 内部调用。

1. 安装交接独立于弹窗：发起安装前同步释放模态对话框，使用不阻塞页面的安装进度面板；原生命令确认接受后立即返回，由持有操作锁的原生任务推进。验证无点击关闭、IPC 返回后仍继续、重复安装拒绝、阻塞或失败重新提示。
2. 明确显示检查任务、退出后台、备份文件、启动安装器各阶段，备份报告文件数与字节数；合并状态刷新为单个在途请求，避免旧结果覆盖新阶段。保留签名、任务准入、退出回执、完整备份、失败恢复和安装前再次验签。
3. 使用隔离数据、确定性原生测试与真实浏览器桥接夹具验证；不运行用户已安装应用、不消耗真实模型。浏览器回归必须在不点击 X 的情况下走完整状态，并覆盖任务阻止、下载取消、重试、慢备份和中英文。
4. 递增至 0.1.7，更新说明和交接文档；完整 CI、原生构建、云端隔离安装、公开安装包与原更新公钥验签通过后发布官网。旧 0.1.6 发起升级仍使用旧更新器，本次安装后的 0.1.7 才具有修复，不能声称修改了既有二进制。

本地实现完成：20 项原生、352 项逻辑、13 项协议、65 项 CI helper、5 项隔离更新服务和 10 项生产构建浏览器桥接场景通过。UI 在每次调用原生安装时断言 `dialog:modal` 为 0，确认原生接受后不等待请求返回继续刷新；慢状态、迟到旧值、失败和双语窄窗均覆盖。源码版本已同步 0.1.7，实际发布待当前提交云端验证。
