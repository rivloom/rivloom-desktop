# 待办、连接诊断与任务文件交付 Implementation Plan

> **执行方式：** 使用 writing-plans / executing-plans 的分项实施与检查点流程，在当前会话继续完成用户已授权的开发。保留原工作区与本地文档提交；不自动推送。真机安装、真实模型与双物理机统一验收由用户稍后安排。

**Goal:** 交付待办与桌面通知、可操作的连接诊断、明确选择的附件和成果传递，使用户能找到待处理任务、解释阻塞并完成跨机文件交付。

**Architecture:** 复用原 Task/Brain/Execution、会话身份、权限、队列和加密通道。待办是现有可见会话的派生视图；通知仅记录去重与偏好。文件采用独立持久存储和小块认证传输，所有文件均绑定任务路由，输入完整后才准入执行；不增加云文件服务或项目同步。

**Tech Stack:** React / TypeScript、Node 24 SQLite、现有 AES-GCM 节点通道、Tauri 2 Windows 原生窗口与通知。

## Task 4：文件存储和边界校验

**Files:** 新增 `shared/task-files.ts`、`server/task-files.ts`、`tests/task-files.test.ts`。

1. 定义文件描述符（随机 ID、文件名、字节数、SHA-256、媒体类型）、任务路由、传输状态与限制。初版单文件 20 MiB、输入最多 10 个/合计 50 MiB，持久文件总配额 512 MiB；使用 32 KiB 数据块。
2. 文件仅由用户明确选择。校验文件名、Windows 保留名/路径分隔符/ADS/敏感凭据名、声明长度和哈希；图片声明检查签名字节。不接收目录、自动解压、执行或打开文件。
3. 独立 SQLite 元数据与受控 blob 文件保存上传、接收进度、路由绑定、重试和失败原因；重复块幂等，冲突块拒绝。最终校验完成才能显示已收到。
4. 写入任务专属新目录，拒绝符号链接/重解析路径逃逸和已有不同内容覆盖。传输哈希只用于明确选择的文件，不扫描项目做结果快照。
5. 测试部分写入/重启、乱序/重复/损坏数据、配额、路径逃逸、空文件和权限绑定。

## Task 5：加密文件传输与任务路由

**Files:** 修改 `server/node-network.ts`、`server/remote-tasks.ts`、`server/brain-tasks.ts`、`shared/types.ts`、`server/index.ts`、`server/task-service.ts`、队列原因类型；新增传输协议与服务测试。

1. 协商 `task-files-v1` 能力。输入清单随任务保存，字节通过原认证通道分块交换；旧节点无能力时在创建前明确拒绝文件任务，普通文字任务兼容保持。
2. 按 local / directed remote / Brain 原路由绑定输入与成果。文件不能通过目录广播或发送给无关节点；Brain 的 Master 按原任务中转给实际 Worker/submitter。
3. 原任务在附件未完整前等待；文件错误不创建第二个 Task 或 session。收到后复制到专属输入目录，并向原 OpenCode 会话提供文件位置；接收的文件本身不扩大工具授权。
4. 成果由执行端用户明确选择发布，沿该任务原路返回；支持原 Task 的完整已结束成果查看，撤信后停止后续传输。
5. 断线/重启保留进度，重试原文件；以认证响应确认偏移和完成，裸 HTTP 成功不作为传输成功。控制消息与文件块共享串行通道但有界分批，避免长文件阻塞审批。
