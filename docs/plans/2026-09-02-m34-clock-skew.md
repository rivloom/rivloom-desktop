# M3.4 回执时差修复 Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 修复正常机器时差导致接受/执行状态误拒绝的问题，保留旧 Execution 拒绝边界，交付可区分的 0.1.2 安装包。

**Architecture:** 延续节点协议已有的 60 秒时差容限，不新增时间同步服务。Worker 回执、执行准备与执行状态相对 Master 创建时间的下界改为 `createdAt - 60_000`；首次接受还必须在 Master 本机的邀请期限内。状态、路由、幂等键和 Execution 序号继续负责去重及失效隔离，时间容差不能复活取消/过期记录。

**Tech Stack:** TypeScript、Node 内置测试/独立进程夹具、现有加密节点通道、官方 OpenCode、Tauri/NSIS。

用户已授权本轮修复、回归和重打包。在现有工作目录实施，保留未提交变更，不创建分支/提交，不改变实际验收 Task、配对、系统时钟或防火墙；不修改 OpenCode，不要求 Project Git/快照/哈希。
