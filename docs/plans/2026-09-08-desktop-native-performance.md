# 桌面底层响应优化计划

目标：在上一轮前端优化基础上，减少桌面后台请求、原生命令和资源采样的同步阻塞。用户授权继续实施；正式桌面操作仍暂停，使用隔离数据验证，不覆盖安装。

1. **资源采样离开请求线程。** 审查并移除首次硬件采集的同步子进程、每次快照的同步磁盘查询与重复 CPU 采样。使用异步初始化、单飞刷新及有界缓存，硬件未知时不发布可调度报告；执行槽位与策略必须立即反映，过期资源不能当新数据。用注入的时钟和延迟探针验证，不查询真实 GPU/WMI。
2. **原生等待进入正确线程池。** 文件选择使用回调接收，通知的同步等待使用阻塞线程池；保持来源、类型、路由、限流和取消语义。使用 Rust 隔离测试证明等待不会占用唯一异步工作线程，不打开原生对话框或发系统通知。
3. **后台事件不扫描整份历史。** 对 SQLite 的任务状态、引擎 session 和远程投递引用建立索引，执行监控/流式事件/槽位统计按需查询，保留完整历史及现有事务行为。验证旧库索引建立、同版本数据更新、回滚、重复引用的顺序与查询计划，并对固定合成历史测量前后读取量及耗时。
4. **核对 WebView2 默认行为。** 检查锁定 Tauri/Wry/Tao 的 DPI、移动与缩放配置；只采用有证据的改动，不添加未经实测的 GPU 参数或进程优先级调整。真实原生拖动、显示合成器和中文输入法仍需恢复实机测试后测量。
5. **集成与交付。** 运行受影响逻辑、Rust、服务隔离检查及类型/双语/生产构建；保存性能证据、更新待测清单。源码与打包安装状态分别记录，Git 仍按整体完成后统一整理。
