# Rivloom MVP 实施计划

**Goal：** 交付一个 Windows 优先、人与 AI 围绕任务协作的可安装产品，完成创建、执行、人工介入、产物审阅和验收，并验证同网段节点自发现、单/多 Brain 协作和两位独立参与者协作。

**Architecture：** React + TypeScript 管理产品界面，Node.js + SQLite 管理本节点承载的 Brain、业务任务、身份、活动和产物。设备是可自发现Node；一个网络可存在一个或多个自动形成的独立Brain，当前只通过共享Worker协作，每个Task固定归属一个Brain，不跨Brain委派或共管。Project、模型与额度由执行Node自治。官方OpenCode只作为执行节点内受保护的loopback后台进程，通过公开API/SDK接入，不修改或fork；桌面交付使用Tauri。当前Brain定义与M3.4范围见 [ADR-0004](../adr/0004-automatic-brain-masters-and-shared-workers.md)，节点身份/发现/信任边界继续遵循 [ADR-0001](../adr/0001-self-discovering-brain-network.md)。

**Tech Stack：** React、TypeScript、Node.js 24、SQLite、OpenCode CLI/SDK 1.18.25、Tauri 2。已确认本机具备 Rust 和 MSVC 构建工具。

**当前执行基线：** 具体顺序以 [里程碑基线](../MILESTONES.md) 为准。M0、M1、M3.1、M3.2、M3.3与M3.4当前MVP范围已完成；纯mDNS92/93专项失败仍保留，不宣称全量绿色。用户于2026-09-03明确选择下一会话修改界面，本会话先保存文档和本地Git，详见 [界面改版交接](../UI-HANDOFF.md)。界面具体要求待用户说明；单Brain目标拆解/任务编排未采纳，不自动启动新功能阶段。M2发行完善、M4登录/更多模型继续暂缓，不能直接实施下文旧任务9或M4。

Windows 桌面端仍是产品形态，浏览器入口只用于内部调试。M3.3 已按 2026-09-01 的产品修正完成可复用能力配置、受信任务自动接收、请求批准/帮我批准/允许任何操作三种 AI 审批、真实本机 OpenCode 执行、有序状态、远程人工介入、补充要求、官方差异和验收。详见 [ADR-0002](../adr/0002-configurable-node-invocation-policy.md) 和 [ADR-0003](../adr/0003-trust-and-ai-approval.md)。

更新日期：2026-09-03。当前目录：`C:\project\rivloom-opencode`。

执行方式：在当前项目内分小步实施，每步记录证据；不要求创建多代理或预先建设其他框架。本轮开发从f5ce9ed开始，用户已授权在当前main保存M3.4及交接的本地提交；新会话核对当前HEAD，不把历史f5ce9ed当作最新基线。不推送、创建分支/worktree或改写历史；用户的Project不要求Git。

## 1. 已确定的约束

1. 产品围绕任务，而非只有聊天。任务状态归本应用管理，引擎会话是任务的一部分。
2. 只接 OpenCode 一个执行引擎。模型供应商适配由 OpenCode 负责，不自研 Agent 循环、上下文管理、模型调用或工具执行器。
3. 使用官方发布程序及匹配 SDK，不复制引擎源码、不修改引擎、不维护 fork。需求若必须改引擎，先说明并建议缩小范围。
4. 客户只安装我们的 Windows 产品；OpenCode 和启动本产品所需的运行时由安装包处理。具体编程项目所需的 Git、语言与构建工具另做检测，不承诺能运行任意项目而无需环境准备。
5. OpenCode Go / Zen 不是使用本产品的必要订阅。本机 Go 已过期，后续不再用该账号做验证，也不自动导入个人凭据。
6. 模型接入先完成 DeepSeek 官方 API。ChatGPT 登录在单独里程碑验证，不将文档支持等同于本产品已经实现或取得商业服务授权。
7. 初期限定可信参与者、已审核普通文件夹和专用测试环境。保留鉴权、人工确认与凭据保护；工作目录限制不构成安全沙箱。
8. 引擎仅绑定 loopback 并鉴权；不得直接暴露公网，不向前端公开引擎地址、密码或通用代理。
9. 节点自发现、设备信任、Brain任务归属和多个独立Brain共享Worker是当前核心范围；不实现跨BrainTask委派/共管。共识数据库、自动故障转移、组织权限、插件市场、自研沙箱、模型额度转售和完整多租户系统继续延后。
10. 旧项目 `C:\project\opencohive` 仅可只读参考产品文档，不复制旧 monorepo，不修改旧项目。

已实现并完成无 Key 运行验证的接口：

| 应用接口                                   | 用途                                     | 权限         |
| ------------------------------------------ | ---------------------------------------- | ------------ |
| `GET /api/model-settings`                  | 返回可选模型、默认模型、配置/验证状态    | 已登录成员   |
| `POST /api/model-settings/deepseek`        | 通过 OpenCode 保存 Key；要求共享额度确认 | 工作区创建者 |
| `POST /api/model-settings/deepseek/remove` | 移除已配置的 DeepSeek 凭据               | 工作区创建者 |
| `POST /api/model-settings/default`         | 设置新任务的默认模型                     | 工作区创建者 |
| `POST /api/model-settings/test`            | 用户确认后，发起可能计费的真实测试       | 工作区创建者 |
| `POST /api/model-settings/test/stop`       | 请求停止测试                             | 工作区创建者 |

交付物：同一网络中的 Rivloom 节点自动发现；用户确认设备信任；一个或多个 Brain 可见并能按任务归属协作；两位真人、两台设备完成真实任务。详细协议边界见 [ADR-0001](../adr/0001-self-discovering-brain-network.md)。

#### 任务 7：节点身份、自发现和真实设备配对

当前拆分：M3.1 的步骤 1 至 3 和附近节点页面已经完成；物理 Win10/Win11 已确认 LAN UDP 回退后的双向发现和签名正常退出。双端配对、信任持久化、重放拒绝、重启保持、撤销和重新配对已通过真实同机双实例、Release WebView2 和用户的物理双机。认证加密通道、Brain 目录、策略化任务调用和真实本机 OpenCode 执行已通过双实例、攻击路径自动化和实际 Release WebView2，待物理双机复测。异常进程结束/断网兜底、发现种子和企业策略仍待后续。设备信任只允许显式开放的最小消息；远端不获得项目路径、模型凭据或通用 OpenCode 权限。

计划涉及：新增节点身份、发现和信任模块；修改 Tauri 生命周期与 Windows 网络权限；新增桌面节点面板和发现验证脚本。

步骤：

1. 每个安装实例生成稳定节点 ID 和设备密钥；私钥使用 Windows 系统保护能力保存，不写入业务 SQLite 或日志。
2. 启动后默认通过 mDNS/DNS-SD 发布最小 Rivloom 服务，并用 LAN UDP 查询/单播回复处理 Windows 单向 mDNS，不要求先创建协作空间。
3. 广播只含协议版本、随机节点 ID、产品端口、公开指纹和粗粒度能力，不含用户、组织、项目、任务、路径或模型信息。
4. 桌面端显示附近节点、在线状态、协议兼容性和指纹；发现自动发生，业务信任由双方短码/指纹确认。
5. 实现受信节点撤销和重新配对；伪造广播、重放确认、已撤销身份和不兼容协议不能进入业务 API。
6. mDNS 与 LAN UDP 都被阻断时提供诊断和已知节点地址发现种子；它只是回退入口，不形成传统主机/访客产品模型。

完成条件：先以多个隔离实例完成自动化验证，再由两台真实 Windows 设备自动发现并完成双端配对；不能把手工切换账号算作通过。

#### 任务 8：Brain 目录与单 Brain 分布式任务闭环

当前进度：加密协作任务使用全局任务 ID、独立幂等键、24 小时期限、双方持久化与通道恢复后重试。执行节点已有持久能力配置；受信任务自动接收，能力关闭时等待，AI 操作由“请求批准 / 帮我批准 / 允许任何操作”控制。匹配任务唯一绑定本机业务任务并启动官方 OpenCode，单调状态与最终摘要回到归属 Brain。归属 Brain 已能按当前执行序号批准/拒绝具体权限、回答 AI、停止、补充要求后继续同一会话、查看 OpenCode 官方差异并验收，控制 ID 持久化去重。旧版 30 分钟准备记录和调用策略已安全迁移。单人双机核心闭环验收后，M3.3 MVP 完成；完整人员角色和其余物理回归延后优化。

步骤：

1. 每个节点都能承载默认 Brain；附近节点能发现一个或多个 Brain，不选举全网唯一主机。
2. 一个任务只有一个归属 Brain，由其保存任务状态机、成员、审批、事件和产物摘要。
3. Brain 为任务选择受信执行节点；执行节点按本机能力开关授权项目和模型，并用任务锁定的 AI 审批模式控制工具，远端不能直接浏览任意本机路径。
4. 执行节点只在本地通过 loopback 调用官方 OpenCode；节点间只交换 Rivloom 任务、控制、进度和经过约束的官方差异消息。策略调用、真实执行、状态、审批/回答/停止/补充和验收均已实现；不扫描或哈希文件夹补齐产物。
5. 两位真人角色、停止/自动审批/撤销和异常断网作为后续物理回归，不阻塞已经验收的 M3.3 MVP。
6. 断网后事件续读与 Brain 离线暂停保留为后续可靠性优化，不在当前切片扩展分布式调度。

MVP 完成条件：物理双机使用真实模型完成“自动发现/信任 → 自动执行 → 人工审批 → 补充要求同会话续跑 → 本地核对 → 远程验收”。该条件已通过；两真人与其余边界回归进入优化清单。

#### 任务 9：最小跨 Brain 委派（历史草案，暂停）

本节已被ADR-0004明确取代，以下步骤只保留历史，不作为当前或下一阶段要求。“每个Node一个Brain”和“Brain A委派Brain B”未采用；当前M3.4共享Worker切片已结项，不需为满足旧草案再做跨Brain委派。

步骤：

1. 两个 Brain 同时被发现并各自保留身份、成员和本地任务；不共写 SQLite 文件。
2. Brain A 能把执行委派给 Brain B 管理的节点，A 仍是任务归属 Brain 和权威状态写入者。
3. 委派消息带任务 ID、归属 Brain ID、幂等键、事件序号和有期限的执行租约，避免断网重发导致重复执行。
4. 两个 Brain 各自发起任务并相互提供执行能力；验证拒绝重复租约、过期租约和伪造结果。
5. MVP 不做自动任务所有权转移、Raft、分布式事务或完整离线多主合并；离线时清楚暂停并由人决定恢复。

历史完成条件（已废止，不用于当前M3.4验收）：两个独立Brain间完成任务委派、人工审批、断网重连和去重。当前验收改为ADR-0004的独立任务归属、共享Worker、最终准入与明确故障边界。
