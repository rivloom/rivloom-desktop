# Rivloom MVP 实施计划

**Goal：** 交付一个 Windows 优先、人与 AI 围绕任务协作的可安装产品，完成创建、执行、人工介入、产物审阅和验收，并验证同网段节点自发现、单/多 Brain 协作和两位独立参与者协作。

**Architecture：** React + TypeScript 管理产品界面，Node.js + SQLite 管理本节点承载的 Brain、业务任务、身份、活动和产物。安装 Rivloom 的设备是可自发现节点；一个网络可存在一个或多个 Brain，并通过任务归属与委派协作。官方 OpenCode 作为执行节点内受保护的 loopback 后台进程，仅通过公开 API/SDK 接入；桌面交付使用 Tauri，将官方引擎和本地服务运行时一起打包。详细决策见 [ADR-0001](../adr/0001-self-discovering-brain-network.md)。

**Tech Stack：** React、TypeScript、Node.js 24、SQLite、OpenCode CLI/SDK 1.18.25、Tauri 2。已确认本机具备 Rust 和 MSVC 构建工具。

**当前执行基线：** 具体顺序以 [里程碑基线](../MILESTONES.md) 为准。M0、M3.1 和 M3.2 已由用户确认完成；用户已经创建 DeepSeek Key，下一步补 M1 真实验证；M2 的正式发行完善暂缓；当前产品开发聚焦 M3.3。M3.4 的 Brain/节点关系仍需讨论，下面的任务 9 仅保留为历史草案，不能视为已确认需求或直接实施。

Windows 桌面端仍是产品形态，浏览器入口只用于内部调试。M3.3 已按 2026-09-01 的产品修正完成可复用能力配置、自动/有限/每项确认策略、真实本机 OpenCode 执行和有序状态回传；继续开发前先对齐跨节点任务的交互和完成条件。详见 [ADR-0002](../adr/0002-configurable-node-invocation-policy.md)。

更新日期：2026-09-01。当前目录：`C:\project\rivloom-opencode`。

执行方式：在当前项目内分小步实施，每步记录证据；不要求新开任务、创建多代理或预先建设其他框架。当前 `main` 已跟踪私有 GitHub 远程仓库，按可运行小步提交。

## 1. 已确定的约束

1. 产品围绕任务，而非只有聊天。任务状态归本应用管理，引擎会话是任务的一部分。
2. 只接 OpenCode 一个执行引擎。模型供应商适配由 OpenCode 负责，不自研 Agent 循环、上下文管理、模型调用或工具执行器。
3. 使用官方发布程序及匹配 SDK，不复制引擎源码、不修改引擎、不维护 fork。需求若必须改引擎，先说明并建议缩小范围。
4. 客户只安装我们的 Windows 产品；OpenCode 和启动本产品所需的运行时由安装包处理。具体编程项目所需的 Git、语言与构建工具另做检测，不承诺能运行任意项目而无需环境准备。
5. OpenCode Go / Zen 不是使用本产品的必要订阅。本机 Go 已过期，后续不再用该账号做验证，也不自动导入个人凭据。
6. 模型接入先完成 DeepSeek 官方 API。ChatGPT 登录在单独里程碑验证，不将文档支持等同于本产品已经实现或取得商业服务授权。
7. 初期限定可信参与者、已审核仓库和专用测试环境。保留鉴权、人工确认与凭据保护；工作目录限制不构成安全沙箱。
8. 引擎仅绑定 loopback 并鉴权；不得直接暴露公网，不向前端公开引擎地址、密码或通用代理。
9. 节点自发现、设备信任、Brain 任务归属和最小跨 Brain 委派是核心产品范围；暂不建设共识数据库、自动故障转移、复杂分布式调度、组织权限体系、插件市场、自研沙箱、模型额度转售或完整多租户系统。
10. 旧项目 `C:\project\opencohive` 仅可只读参考产品文档，不复制旧 monorepo，不修改旧项目。

## 3. 实施顺序与完成条件

### M0：保留并复核现有基线（已完成，改动后回归）

交付物：现有任务闭环、真实引擎探针、独立身份协作协议和验证报告。

- 复用现有代码，不重新搭架构。

- 新报告记录引擎版本、所用模型、时间、实际结果和失败，不覆盖历史事实。

### M1：把模型接入做成产品功能（功能已完成；真实 DeepSeek 回归待 Key）

交付物：模型设置页、DeepSeek 凭据管理、连接验证、默认模型和任务选择联动。

**使用边界：** 当前是一台共享执行主机，DeepSeek API 按工作区配置，仅创建者管理。保存前明确确认可信成员的任务会使用该额度。此阶段不声称每个成员拥有独立的模型凭据或计费账户。

#### 任务 1：验证并收敛后端草稿（已完成）

涉及文件：

- 修改：`server/model-settings.ts`、`server/task-service.ts`、`server/index.ts`。
- 修改：`server/store.ts`、`shared/types.ts`。
- 新增：`scripts/model-settings-check.ts`。

步骤：

1. 在独立测试数据目录启动真实的官方 OpenCode 1.18.25。
2. 验证 `auth.set` / `auth.remove` 保存与移除凭据，以及 `provider.list` 返回模型。
3. 验证凭据变更后的公开缓存刷新方式；当前草稿使用 `global.dispose`，必须确认不会丢失历史会话或影响后续审批流。
4. 只在无执行任务、无未确认中断、无连接测试时允许凭据变化；与任务启动串行保护，避免检查后又有任务启动的竞争。
5. 处理“凭据操作已提交，但刷新失败”的不确定状态，清楚提示重启核对，禁止悄悄使用陈旧模型配置。
6. API 只返回必要状态与模型标识，不返回原始 provider 配置、请求头、Key、OAuth token 或上游错误体。

已实现并完成无 Key 运行验证的接口：

| 应用接口                                   | 用途                                     | 权限         |
| ------------------------------------------ | ---------------------------------------- | ------------ |
| `GET /api/model-settings`                  | 返回可选模型、默认模型、配置/验证状态    | 已登录成员   |
| `POST /api/model-settings/deepseek`        | 通过 OpenCode 保存 Key；要求共享额度确认 | 工作区创建者 |
| `POST /api/model-settings/deepseek/remove` | 移除已配置的 DeepSeek 凭据               | 工作区创建者 |
| `POST /api/model-settings/default`         | 设置新任务的默认模型                     | 工作区创建者 |
| `POST /api/model-settings/test`            | 用户确认后，发起可能计费的真实测试       | 工作区创建者 |
| `POST /api/model-settings/test/stop`       | 请求停止测试                             | 工作区创建者 |

完成条件：真实引擎上的凭据生命周期和缓存刷新通过；越权、运行中修改、重复操作、不确定结果处理都有证据。使用测试字符串验证保存/删除，只能算接口验证，不能标为 DeepSeek 已连接。

#### 任务 2：补齐凭据与验证状态管理（已完成）

涉及文件：`server/model-settings.ts`、`server/store.ts`、`tests/security.test.ts`；必要时新增 `tests/model-settings.test.ts`。

步骤：

1. 保存 Key 后显示“已配置、未验证”，更换 Key 后清除旧验证结论。
2. 区分未配置、已配置未验证、测试中、测试通过、测试失败、测试中断。
3. 连接测试只调用一次 OpenCode 会话；使用独立无业务文件的目录，并禁止全部工具。只发送固定测试提示，不附带用户项目。
4. 增加明确的超时、停止、清理和重启恢复行为；不由应用自动重试收费请求。
5. 测试状态、默认模型及操作人/操作时间可追踪；业务数据库中不保存 Key 或模型测试原文。

#### 任务 3：实现模型设置界面（无 Key 范围已完成）

涉及文件：新增 `src/model-settings.tsx`，修改 `src/main.tsx`、`src/styles.css`、`src/api.ts`、`shared/types.ts`。

步骤：

2. DeepSeek 卡片提供密码式 Key 输入、保存/替换、确认移除；提交完成后清空输入，不回显完整凭据。

4. 模型列表由 OpenCode 返回，不自行硬编码一个永久有效的模型目录。
5. 连接测试前说明会发起一次实际模型请求、可能计费；运行时显示进度和停止入口。
6. 默认模型只影响新任务；已有任务保留原模型，不因配置改变而静默切换供应商。

当前拆分：M3.1 的步骤 1 至 3 和附近节点页面已经完成；物理 Win10/Win11 已确认 LAN UDP 回退后的双向发现和签名正常退出。双端配对、信任持久化、重放拒绝、重启保持、撤销和重新配对已通过真实同机双实例、Release WebView2 和用户的物理双机。认证加密通道、Brain 目录、策略化任务调用和真实本机 OpenCode 执行已通过双实例、攻击路径自动化和实际 Release WebView2，待物理双机复测。异常进程结束/断网兜底、发现种子和企业策略仍待后续。设备信任只允许显式开放的最小消息；远端不获得项目路径、模型凭据或通用 OpenCode 权限。

3. 广播只含协议版本、随机节点 ID、产品端口、公开指纹和粗粒度能力，不含用户、组织、项目、任务、路径或模型信息。
4. 桌面端显示附近节点、在线状态、协议兼容性和指纹；发现自动发生，业务信任由双方短码/指纹确认。
5. 实现受信节点撤销和重新配对；伪造广播、重放确认、已撤销身份和不兼容协议不能进入业务 API。
6. mDNS 与 LAN UDP 都被阻断时提供诊断和已知节点地址发现种子；它只是回退入口，不形成传统主机/访客产品模型。

完成条件：先以多个隔离实例完成自动化验证，再由两台真实 Windows 设备自动发现并完成双端配对；不能把手工切换账号算作通过。

#### 任务 8：Brain 目录与单 Brain 分布式任务闭环

当前进度：加密协作任务使用全局任务 ID、独立幂等键、24 小时期限、双方持久化与通道恢复后重试。执行节点已有持久能力配置，支持自动/有限/每项确认；匹配任务唯一绑定本机业务任务并启动官方 OpenCode，单调状态与最终摘要回到归属 Brain。旧版 30 分钟准备记录安全迁移且不可自动执行。实际 Release WebView2 已验证真实第二节点发任务、随包 OpenCode 生成预期文件和远端隐私边界。下一步是人员角色、远程审批/回答/补充/停止、差异/产物和验收。

步骤：

1. 每个节点都能承载默认 Brain；附近节点能发现一个或多个 Brain，不选举全网唯一主机。
2. 一个任务只有一个归属 Brain，由其保存任务状态机、成员、审批、事件和产物摘要。
3. Brain 为任务选择受信执行节点；执行节点按本机预设的自动/有限/每项确认策略授权项目和模型，远端不能直接浏览任意本机路径。
4. 执行节点只在本地通过 loopback 调用官方 OpenCode；节点间只交换 Rivloom 任务、控制、进度、差异和产物消息。策略调用、真实执行和状态已完成，审批/停止/产物仍待实现。
5. 两位真人分别完成发起、接受、启动、审批、补充、停止、查看差异和验收，并验证越权请求和撤销后的请求被拒绝。
6. 断网后事件可续读；Brain 离线时任务明确暂停，不静默迁移或继续产生副作用。

完成条件：两位真人在两台 Windows 设备完成“自动发现 → 配对 → 发现 Brain → 分配执行节点 → 执行与审批 → 产物验收”的真实编程任务。

#### 任务 9：最小跨 Brain 委派（历史草案，暂停）

本节尚未获得产品确认。尤其是“一台节点承载一个 Brain，再由 Brain A 委派给 Brain B”的描述可能与目标产品不一致；双方重新定义 Brain、节点和任务关系前，不进入实现。

步骤：

1. 两个 Brain 同时被发现并各自保留身份、成员和本地任务；不共写 SQLite 文件。
2. Brain A 能把执行委派给 Brain B 管理的节点，A 仍是任务归属 Brain 和权威状态写入者。
3. 委派消息带任务 ID、归属 Brain ID、幂等键、事件序号和有期限的执行租约，避免断网重发导致重复执行。
4. 两个 Brain 各自发起任务并相互提供执行能力；验证拒绝重复租约、过期租约和伪造结果。
5. MVP 不做自动任务所有权转移、Raft、分布式事务或完整离线多主合并；离线时清楚暂停并由人决定恢复。

完成条件：两个独立 Brain 之间完成真实任务委派、人工审批、断网重连和去重验证。只有此项通过后才能宣称“多 Brain MVP”。

### M4：按需开放 ChatGPT 登录和其他模型

交付物：逐项经过验证的接入方式，不承诺“所有模型、所有订阅均可用”。这不是 M1 的前置条件，也不引入第二个执行引擎。

#### 任务 10：验证 ChatGPT 官方支持的登录路径

计划涉及：`server/model-settings.ts`、`src/model-settings.tsx`、`docs/ENGINE.md`、`SECURITY.md`；只使用 OpenCode 的公开提供方认证接口。

步骤：

1. 核对发布时 OpenCode 和 OpenAI 官方文档、账号适用范围及第三方商业客户端使用边界。
2. 通过公共认证方法发现、授权和回调接口接入，不仿冒 OAuth 客户端、不抓取登录 Cookie、不要求客户提供密码。
3. 实测登录、取消、失败、令牌续期、退出和移除，以及浏览器回调在 Windows 安装包中的行为。
4. 明确实际可用模型、订阅用量限制与 API 独立计费的区别，不宣传无限 API 权限。
5. 个人订阅只用于其被允许的账号本人场景。当前工作区共享 DeepSeek API 的方式不能直接套到 ChatGPT 个人订阅上；多人凭据归属与任务用量隔离需要单独设计和核对。
6. 若必须修改引擎或认证/授权边界无法确认，暂不开放这一入口，继续提供已验证的官方 API Key 接入。

完成条件：使用用户明确授权的真实账号跑通完整任务及退出流程，且产品宣传与实际授权范围一致。未登录实测或条款未确认时，继续标记待验证。

### M5：形成可交付的商业内测版本

#### 任务 11：发布检查

计划涉及：`THIRD_PARTY_NOTICES.md`、`docs/licenses/`、`docs/dependency-licenses.json`、`docs/engine-lock.json`、`SECURITY.md`、`README.md`、新增 `docs/RELEASE_CHECKLIST.md`。

步骤：
