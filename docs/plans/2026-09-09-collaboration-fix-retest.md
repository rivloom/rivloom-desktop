## 已修正的代码

1. **软件能力过早失效。** 原 60 秒缓存从探测结束计时，加上 60 秒目录扫描，会跳过下一次探测。实机派发时远端 Python 证据为 121,309 毫秒，超过 120,000 毫秒有效期，导致远端被排除。改为从探测开始计算 30 秒缓存，保证每分钟扫描会重新探测；配置变化立即探测，旧的异步结果不能覆盖新的缓存。
2. **原始约束与执行阶段不明确。** 协作规则通过官方 OpenCode `system` 参数发送；原始要求、目录数据和文件内容保留在任务消息。说明 write 会创建父目录，禁止命令时不能为了目录检查而例外；当前执行明确 Node 身份，只完成当前步骤。要求一个步骤时不把建目录、读写文件和汇报机械拆分。
3. **接收端重做源端工作。** 接力后的当前要求改为检查点中的剩余工作；原始计划及完整用户约束仍保留。接收端任务记录也显示本次剩余要求。
4. **文件返回原 Node 时来源冲突。** 每次远端执行对输入文件建立稳定的新传递标识，分块复制并校验相同内容，再绑定到该次执行。不修改原文件的上传者或对端来源绑定，不允许第三方抢占旧标识；重试和重启复用已完成的同一份中转文件。

write 创建父目录及系统提示合并行为已核对官方 OpenCode 1.18.25 源码：[write 实现](https://github.com/anomalyco/opencode/blob/v1.18.25/packages/opencode/src/tool/write.ts)、[模型请求构造](https://github.com/anomalyco/opencode/blob/v1.18.25/packages/opencode/src/session/llm/request.ts)。
