# 已停止任务滞留执行队列修复

用户截图中的协作任务已经确认停止，本机引擎也已恢复正常，但对应队列仍是 `admitted / started`，步骤里继续显示重启前的引擎退出报错。只读核对确认实际 Task 为 `stopped`；槽位统计已经忽略该 Task，主要问题是队列记录没有收尾和当前提示过时。

## 修改

- 队列恢复识别绑定 Task 的 `stopped` 状态，以 `ended / stopped` 收尾；覆盖已有持久化记录。本机与远端都使用真实 Task 状态，远端收尾不依赖发起设备在线。
- 正在停止、审批等待、执行中、状态未知及绑定不匹配仍保留，不把停止请求当作停止成功，也不重建会话。
- 界面立即移除已确认停止的执行项，保留历史会话。用户明确继续普通任务时，仍使用原 Task 与官方会话；结束的自动队列不会重新入队，执行栏按当前 Task 状态显示。继续操作仍检查人员权限、设备信任、原投递、项目与执行槽，以及原会话是否空闲；拒绝、撤信等结束原因仍不可绕过。
- 已停止步骤的旧错误显示在折叠的执行记录中，不再作为当前红色故障。旧数据无需重新停止即可获得正确显示。
