# Desktop Updater Implementation Plan

> 执行技能：使用本会话已读取的 `executing-plans` 按步骤实施。用户已授权本轮开发；保留当前未提交成果，不另建旧基线、不自动提交或发布。

**Goal:** Rivloom 启动及定期检查官方新版，允许跳过单个版本，用户选择更新后下载、验签并在安全退出后启动安装。

**Architecture:** 延续 Windows x64 / `com.rivloom.desktop` / currentUser NSIS。使用固定官方 HTTPS 更新清单和 Tauri 官方 updater；原生包装命令沿用精确窗口与 origin 校验。更新前由本地服务封闭新准入、检查在途执行并创建应用状态备份；不把更新行为等同于强制停止任务。

**Tech Stack:** Tauri 2 / Rust updater、React / TypeScript、Node.js SQLite、本地受控夹具、既有 GitHub Release / R2 发行流程。

---

## 用户范围与默认行为

- 2026-09-09 用户要求现在实现；启动后后台检查，随后每 6 小时检查。网络失败不阻塞启动、不循环弹错；“关于 Rivloom”提供手动检查与可见错误。
- 新版本提示版本号、更新说明和“跳过此版本 / 下载并安装”。跳过选择持久保存；更高版本继续提醒，手动检查可以重新找到跳过的版本。
- 下载显示进度，失败可重试；验签成功之前不能启动安装。安装完成由官方 NSIS updater 流程重启应用。
- 运行、待审批/提问、未知执行、尚未完成的协作与在途投递不能被更新静默结束。首版在存在不安全工作时保留下载，说明阻塞原因并允许稍后重试安装。
- 本轮不操作正式安装、不恢复暂停的物理机或真实模型测试、不提交/推送/发布。隔离工程验证继续进行。
- 现有不含 updater 的旧安装需要先由用户手动安装首个含本功能的版本；上线清单不能为旧二进制凭空增加代码。

## Task 1: 更新契约与发行签名

**Files:** `src-tauri/Cargo.toml`、`src-tauri/tauri.conf.json`、新增 updater 模块与签名/频道发布脚本、既有 CI 发行配置。

1. 核对并锁定官方 updater 版本及 Windows 安装退出行为。
2. 建立正式内置公钥与本地受限私钥保存流程；私钥不得进入源码、运行时、报告或日志。
3. 更新清单独立于现有手动下载记录；绑定正式版本、平台、受控下载 URL 和实际安装包签名。
4. 复用已验收且匿名字节核验通过的公开安装包，最后以条件写入推进更新频道。拒绝相同版本不同字节、降级和占位签名。
5. 用本地夹具测试清单、签名、源地址和发布竞争；不访问外部写入接口。

## Task 2: 原生检查、下载及跳过状态

**Files:** 新增 `src-tauri/src/desktop_update.rs`、修改 `src-tauri/src/main.rs`、`src-tauri/build.rs`、权限配置。

1. 实现受控状态机与持久跳过版本；前端不能提供任意下载 URL、公钥、路径或安装参数。
2. 后台检查不阻塞窗口；合并重复检查、下载和安装请求。
3. 使用固定 HTTPS 源、超时、签名校验；提供进度、取消与固定错误码。
4. 下载成功与安装成功分开；失败保留原程序与可重试状态。
5. Rust 测试覆盖版本、持久状态、签名失败和状态竞争。

## Task 3: 安装生命周期与状态保护

**Files:** 新增服务更新维护模块、修改 `server/index.ts` / `server/node-network.ts` / 原生 runtime 生命周期；应用状态兼容守卫与备份。

1. 在隔离数据根构造执行、队列、工作流及未知状态反例。
2. 安装前封闭新准入，等待在途操作完成并重新检查；不修改用户永久执行策略。
3. 不安全时解除维护状态并返回具体类别；安全时确认自有服务和引擎退出，再备份完整的应用持久状态。
4. 备份覆盖 SQLite/WAL、JSON、身份、信任和引擎关联数据，排除 WebView 缓存/临时日志且不遍历用户项目。
5. 新版本对未来数据格式拒绝写入；保留故障现场和备份，安装器启动失败时提供明确恢复路径。
6. 用受控服务验证拒绝重复执行、维护释放、重启保留身份和数据；不运行正式安装器。

## Task 4: 更新界面

**Files:** 新增 `src/desktop-update*.ts(x)` / 样式，修改 `src/desktop.ts`、`src/main.tsx`、`src/about-rivloom.tsx` 与中英文资源。

1. 接入新版本提示、跳过、下载进度、失败重试与安装被任务阻塞的状态。
2. 关于窗口提供当前版本、上次检查、手动检查和重新选择跳过版本。
3. 保留结果优先布局和已有工作流交互；浏览器/Preview 不执行正式更新。
4. 使用生产构建与原生桥接夹具核对中英文、键盘、窄窗口和重复点击。

## Task 5: 验证与交接

1. 运行更新相关单元、受控服务、Rust 和 UI 检查。
2. 运行类型、国际化、生产构建及改动影响到的既有回归与 CI helper 检查。
3. 更新依赖许可和交接文档，写明真实通过项、未进行的安装/公网验证、首次手动接入与正式发布配置。
4. 若生成本地候选，保留新的源码摘要和证据，不覆盖 `a95315c1` 或已公开同版本文件。用户自行安装。

Task 1–4 已完成；Task 5 的类型、国际化、生产 UI、逻辑/协议、CI helper、Rust、隔离更新服务与官方引擎检查通过。代码版本同步 0.1.5。详细范围、密钥保管、签名频道与恢复边界见 [应用内更新](../DESKTOP-UPDATES.md)。本地候选构建/解包结果保留于 .data/verification/desktop-updater-candidate-20260909/，未执行正式安装器。

实现中另补两处实际问题：后台下载在受阻时重新打开说明；Escape 默认关闭浏览器 dialog 会绕过安装准备保护，现由统一 close 回调控制。进程宿主也收紧为确认 engine tree 退出才返回成功，避免把 taskkill 失败当成可安装状态。

不改变原始用户任务的范围：新有序迁移、自动回滚、Windows Authenticode 和真实升级矩阵仍待独立验收；当前无 schema 变更，仅拒绝未来格式。未提交、推送、发布或调用外部模型。
