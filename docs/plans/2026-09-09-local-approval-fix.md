# 本机执行审批修复记录

用户反馈：在“本机执行能力”选择“帮我批准”后，仍需手动批准；本机发起和另一台电脑交给本机的任务都会遇到。

## 已确认的问题与修改

1. 新任务编辑器把审批模式固定初始化为 `ask`，忽略已保存的本机默认值。改为“跟随本机设置（当前模式）”；保存设置后，新任务自动使用最新默认值。用户为任务明确选择的模式仍优先，提交请求携带实际模式。
2. 普通任务（包含接收到的普通远端任务）的提示词固定写着“每次修改和命令等待审批”，与 `auto/full` 的官方权限规则矛盾。移除此固定指令，按该任务创建时的模式向官方引擎传入系统说明；只读规划仍保持只读，不放宽原始用户约束。
3. 执行能力表单的草稿值与已保存值容易混淆。现在分别展示已保存模式、未保存提示和作用范围；保存失败不会声称已生效，重新打开使用服务端确认的值。
4. 回归中新复现 OpenCode 1.18.25 的兼容问题：`webfetch` 未填写可选 `timeout` 时，旧权限列表接口因 metadata 中的 `undefined` 返回编码错误，阻断整个任务状态同步。[该版本官方工具代码](https://raw.githubusercontent.com/anomalyco/opencode/v1.18.25/packages/opencode/src/tool/webfetch.ts)与实际日志一致。官方 `permission.asked` 事件仍返回有效请求，因此增加有界的事件缓存：仅在列表读取失败时使用同目录、同会话、仍连接的官方请求；沿用原始请求 ID 和官方审批回复接口。回复后清除，断流失效，迟到列表不能覆盖新事件；不构造审批、不自动同意联网请求。

## 保持的行为

- “帮我批准”：项目内修改和命令自动执行，联网仍需人工批准。
- “请求批准”：修改、命令和联网仍走原有审批。
- 已有任务保留创建时的模式；修改默认设置不会批准旧的待审批操作。
- 远端执行由接收电脑保存的策略控制，发起电脑的模式不能覆盖它。
- 使用官方 OpenCode 1.18.25 和锁定依赖；没有修改、替换或模拟引擎。
