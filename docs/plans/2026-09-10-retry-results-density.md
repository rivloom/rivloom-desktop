# Workflow Recovery and Compact Results Implementation Plan

**Goal:** 支持失败业务步骤单独重试，把回答与交付成果清晰呈现，远端成果按需取回，并提高对话信息密度。

**完成状态（2026-09-11）：** 四部分已实现并验证，详见 [功能说明](../WORKFLOW-RECOVERY-RESULTS.md) 和 [验证记录](../VERIFICATION.md) 顶部。当前仅允许整轮结束为失败后重试选中步骤；历史轮次、未确认执行和旧节点不开放远端重试。远端最终成果按需取回，同一计划的依赖材料仍经协调端传递；后续轮次只引用结果时不下载。未打包或发行。

**Architecture:** 保留现有工作流、轮次、稳定执行 ID、附件鉴权和传输协议。重试创建新的 attempt 并保留旧记录；新版本节点协商成果按需传输，完成状态不再依赖本机已有文件字节。展示复用现有 Markdown、文件预览和执行过程组件，使用紧凑排版。

**Tech Stack:** React、TypeScript、SQLite、官方 OpenCode、现有加密协作通道与分块文件传输。

在当前用户指定工作区实现，保留输入框和原有文档改动。用户已授权本轮实施；不增加任务模板、项目配置、全文搜索或会话导出。测试只用独立数据、合成模型/节点，暂不操作用户安装版、真实项目、真实模型或发布链路。

## 1. 失败步骤重试

- 修改 `shared/workflows.ts`、`server/workflow-service.ts`、`server/workflow-api.ts`、`server/workflow-runtime.ts` 与 `src/workflow-view.tsx`。
- 仅允许当前轮失败业务步骤；拒绝已完成、执行中、未知执行、历史轮次与旧版本请求。通过版本、轮次、最后 attempt 及持久请求标识限制重复点击与重放。
- 重试前重新确认旧执行已结束，无法确认时保留失败状态。旧 attempts、已完成前置及并行分支成果保持完整；仅重新激活该步骤和尚未执行的受阻后续依赖。
- 追加新执行记录，保持会话身份；消息队列保持原暂停状态，不能因点击重试误执行下一条消息。
- 在 `tests/workflow-service.test.ts` 等现有测试文件补充失败→重试→后续完成、多个失败分支、重启、防重、停止/下一轮竞争、材料继承与确认失败测试。

## 2. 远端成果按需取回

- 修改工作流 runtime/context/channel、`server/node-network.ts`、文件 API 和 `src/task-files.tsx`。
- 先查清自动回传入口 `repairFileRoutes()` 与 `WorkflowRuntime.lookup()`。增加明确的协商能力与持久传输策略，保持旧节点原有行为；signed hello 保持最多 12 项能力。
- 新执行的远端成果默认只同步经过认证的文件描述与结果；执行机器保留产物与现有校验快照。界面显示机器、文件名/路径及“取回到本机”，完成取回后才允许本机预览/打开。
- 文件取回须绑定原 workflow、execution、digest、manifest 和用户可见性；按所选文件排队，沿用分块、哈希、重试和撤信保护。不能通过摘要中的任意路径读取文件。
- 后续业务步骤确实需要的输入沿用按需材料传递；规划阶段只需结果记录时不触发整批远端文件下载。
- 在现有 workflow/context/file/network 测试与隔离双服务夹具覆盖：未取回时零文件传输、单文件取回、防越权/旧执行、重启、离线重试、依赖取材、旧版本兼容。

## 3. 结果展示与对话密度

- 修改 `src/workflow-view.tsx`、`src/workflow-results.ts`、`src/conversation-workspace.tsx` 及对应 CSS、`src/message-markdown.css`。
- 本轮回答、交付文件和执行详情分层；结构化 Markdown 保持语义，避免重复标题/状态/路径和把内部结构原文挤进回答。多成果按步骤清楚标识，失败时仍能查看已完成部分。
- 缩小消息、轮次、分隔线和过程面板间距，提高同屏内容量；正文保持可读，代码/表格可横向滚动，长详情按需展开。
- 保留最近完成的简洁输入框、复制、选择、草稿、附件、队列与即时中英切换。

## 4. 验证与交接

运行新增定向测试、逻辑回归、版本一致性、测试分类、双语/类型与生产构建。用隔离 UI 验证短/长回答、表格/代码、多轮、多个文件、远端未取回/取回中/失败、步骤重试、窄窗与键盘操作，并逐张核对截图。

记录真实通过项与限制，更新 NEXT-SESSION/HANDOFF/VERIFICATION。未获后续发行安排前维持本地开发状态，不把浏览器夹具称为原生或双物理机验收。
