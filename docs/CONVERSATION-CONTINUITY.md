# 连续会话、草稿与附件

更新：2026-09-10，0.1.12。

## 连续会话

新建及已有的工作流会话可以在完成后继续输入要求；执行中发送的消息先排队，当前轮成功结束且所有执行已经结束后自动按发送顺序开始下一轮。模型的问题在问题卡片里直接回答，回答属于当前轮，不进入队列。停止或失败会暂停消息队列，核对结果后可继续队列；未执行消息可取消。最多同时排队 50 条，每条最多 12,000 字符和 5 个附件。早期普通 Task/Brain 记录沿用原有继续规则，新会话统一使用工作流。

会话 ID、名称、目录、模型、设备选择和用户偏好保持稳定，完整要求、完成条件、问题回答、结果摘要及文件清单按轮次保留。下一轮重新规划，并通过完整 JSON 会话记录和已有成果继续；同名文件使用最近成果或本轮新附件。跨设备仍遵守目标设备权限与执行准入。引擎会为新的规划/步骤创建会话，并非复用一个无限增长的引擎 session。

材料沿用每个步骤最多 10 个、合计 1000 MiB 的限制，会话记录文件计入材料数；超限会明确暂停而非静默丢弃文件。含未执行消息的会话须先取消队列后才能移入回收站。自动接续消息阻止更新交接；显式暂停的终止轮次队列允许更新，重启后保留。

## 阅读与草稿

应用回答和结果支持标题、列表、表格、引用、行内代码、带语法高亮的代码块和独立代码复制；整条消息复制仍保留 Markdown 原文。HTML 不执行，Markdown 远程图片只显示说明，HTTP/HTTPS 链接在独立目标打开。

每个会话和新会话分别保存未发送文字、设备路由、提交请求标识与已上传附件；目录、模型、审批选项和完成条件也会恢复。草稿按当前设备与用户隔离，同时保存在浏览器和本机服务，服务重启或端口变化不丢失。只有确认发送成功才清空相应草稿；重复请求复用原标识。未上传完的文件不能从文件名还原，恢复后明确提示移除并重新选择。永久删除会清理对应草稿，过期客户端不能恢复已删除的内容。

## 附件

输入框支持 Ctrl+V 粘贴截图，附件文件可以拖入或通过选择器上传；完成上传后可预览。图片支持 PNG/JPEG/GIF/WebP，文本和代码最多预览前 256 KiB，音视频使用浏览器内置播放器与分段读取。HTML/SVG 等作为纯文本显示；其他格式保留下载后打开的提示。图片预览上限 20 MiB，具体音视频编码的播放能力取决于 WebView。所有预览继续检查上传者或实际任务成员权限，项目原始文件不受清理影响。
