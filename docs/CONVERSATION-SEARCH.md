## 使用方式

在左栏“搜索会话”输入关键词。结果保留原来的目录分组与置顶顺序，每条会话显示一个匹配片段及片段数量；点击标题或片段打开会话。上方的前后按钮可以切换该会话中的匹配片段，并循环回到第一处。搜索定位会展开对应的历史轮次、步骤和执行尝试，关键词在可见正文中高亮。

- Enter 打开筛选结果中的第一条会话；输入法组合期间的 Enter 不触发打开。
- Escape 或搜索框中的清空按钮清除关键词；状态和来源筛选继续保留。“清除筛选”同时清除这三项。
- 右侧关闭按钮退出本次定位，保留搜索列表；“回到最新消息”也退出定位。
- 搜索和定位不会发送消息、重试步骤、恢复队列或取回远端文件。未发送草稿保留。

## 搜索范围

包含标题、工作目录及别名、来源设备名、已保存的需求、旧式会话回答、工作流各轮需求和最终/部分成果、计划说明、步骤的历史结果或检查点，以及尚未执行的排队消息。旧式会话的完整需求（含已保存补充）显示在需求正文中；即使旧记录只剩回答，需求也有独立的定位入口。

仅搜索当前账号可见、尚未进入回收站的本机已同步记录。恢复后重新出现；永久删除后不保留可搜索的副本。不会扫描工作目录或远端文件，不搜索附件正文、工具输出、引擎提示封装、模型配置、未发送草稿、取消的排队消息。工作流执行原文和资源证据不作为最终回答加入搜索。

匹配采用忽略大小写的连续字面文本，前后空白忽略，不使用正则表达式、模糊搜索或语义搜索。输入最多 200 字符。数量按匹配的**文本片段**计，一段回答里重复出现多次只计一个片段，并高亮其中的可见匹配。Markdown 按保存的原文搜索；格式符号可能只在搜索摘要中可见，正文仍按 Markdown 正常呈现。复制结果或代码保持原始文本，不携带高亮标记。

## 实现与边界

`src/conversation-search.ts` 基于服务端已经鉴权、经过历史过滤的 bootstrap 生成内存索引；非搜索状态不建立索引。查询使用 React 延后渲染，避免阻塞输入事件；索引和匹配随当前数据更新，没有持久化搜索库或新增网络接口。索引不截断长消息，摘要只截取首个匹配附近的上下文。

定位身份包含轮次、步骤、执行尝试或消息标识。查旧记录时，历史执行标签使用该次执行的真实阶段，不再沿用当前步骤的失败标签。后台更新期间不强制把正在读旧匹配的用户拉回最新消息。

一万条合成会话、五万个片段、约 5074 万字符的单次内存基准中，索引约 20ms、查询约 3ms；这是本机算法测试，不代表实际历史全量渲染、原生帧率或长期负载验收。

## 明天的隔离验收

本机已准备 `.data/verification/conversation-search-20260913/打开搜索验收.cmd`。双击后打开浏览器预览，只使用演示记录，不调用模型。窗口里的设备名为“搜索验收 · 演示数据”；在命令窗口按 Ctrl+C 可关闭服务。数据只在该进程内存在，关闭后重置；预览不支持真实任务执行。

| 搜索词 | 预期行为 |
| --- | --- |
| 深海蓝 | 找到“海报设计与修改”；两个匹配片段来自第一轮需求和回答。点击后前后切换，定位第一轮。 |
| 珊瑚橙 | 定位同一会话第二轮，和第一轮分开。 |

| Safari | 找到旧式会话中保存的补充要求。 |
| C++ [draft] | 按字面字符搜索，能找到代码；复制代码不带高亮标记。 |
| 离线恢复 | 定位待执行消息，消息队列仍暂停。 |

可以再试一次：在新会话中写一份草稿，搜索并查看旧回答，然后回到新会话，草稿应保留。状态/来源筛选、中英文切换和窄窗口也可直接验收。

其他开发环境可运行 `npm run preview:search`，重新构建并打开同类合成预览；需要 Node.js 24+ 和已安装的仓库依赖。固定本机预览使用本轮冻结的 `preview-dist`，不会被后续构建覆盖。
