# Rivloom Mac Preview

这是 Apple Silicon（M 系列）macOS 桌面测试构建，最低配置为 macOS 14。应用名称为 **Rivloom Mac Preview**，标识为 `com.rivloom.macospreview`；使用独立数据目录，不替换 Windows/Linux 正式渠道，也不启用应用内自动更新。Intel Mac 暂不提供构建。

## 安装与使用

从对应提交成功的 **macOS Apple Silicon preview** 工作流下载测试产物，解压后打开 DMG，将应用复制到 Applications 再启动。包采用 ad-hoc 临时签名，没有 Apple Developer ID 签名或公证；云端启动检查不代表从互联网下载后的 Gatekeeper 验收。若系统阻止启动，应先核对来源和验收报告，并按系统提供的安全设置处理，不要关闭整个系统的安全保护。

首次打开后，在「设备与模型 → 模型与执行」配置模型及可信的本机执行目录，再新建会话。实际模型使用对应账号的额度。节点配对仍需两端核对短码并分别确认；云端双节点测试使用回环网络与确定性模拟模型，不能代替物理局域网或真实提供商验收。

关闭窗口后应用留在菜单栏，点击 Dock 图标可重新打开。通过应用菜单或菜单栏的退出操作结束应用和后台执行。Finder 中打开文件、定位文件与打开项目目录可用。Windows 防火墙修复、Windows 系统通知、提示音和选择其他打开程序的入口在此预览中不可用。

## 身份与进程

节点私钥保存于当前用户的 macOS 钥匙串；数据文件只记录引用和公钥信息。重启应保留同一节点身份。钥匙串锁定、拒绝访问或原条目缺失时，节点网络保持关闭，不静默生成替代身份；请先处理钥匙串访问问题。复制数据目录到另一台 Mac 不能替代正常配对或迁移流程。

原生进程助手建立独立进程组并保存出生时间，以免误停止复用 PID 的其他进程。应用退出后通过专用控制管道关闭引擎及所跟踪的后代；无法证明进程已退出时保留未知状态，不自动确认转交。该机制不保证跟踪任意刻意逃逸并完全脱离的守护进程。

## 从源码构建

Windows 可修改代码和发起 GitHub Actions；实际编译、签名和 DMG 打包必须在原生 Apple Silicon Mac 上执行。安装 Xcode Command Line Tools、Node.js 24.19.0 和 Rust 1.98.1 后，在仓库根目录执行：

```sh
npm ci
npm run desktop:build -- --config src-tauri/tauri.macos.conf.json
```

Tauri 的构建前命令已包含前端与随包运行时准备，无需先重复运行 `desktop:prepare`。首次准备会按 `shared/engine-source-macos.json` 核验固定 OpenCode 源码、依赖锁、Bun 和构建配方，然后原生编译并执行核心验收。相同输入且核验通过的产物会复用。

产物在 `src-tauri/target/release/bundle/dmg/`。包内含 Node、固定核心、钥匙串与进程助手、平台对应依赖许可原文和哈希清单。不要在打包后重新签名内嵌程序再沿用旧清单；正式开发者签名、公证和分发必须另行设计并重新验收。

## 云端验收范围

工作流先编译并测试原生助手，再创建仅用于该临时 runner 的测试钥匙串。随后检查跨进程身份、核心流式响应与批准/拒绝/取消、模型配置持久化、双节点配对和加密任务结果、原生 Rust 行为、DMG 挂载与复制、最终包哈希、应用启动/退出和重启身份。结束时恢复 runner 原有钥匙串设置。只有全部强制检查成功后才上传 DMG。

请查看与下载产物相同提交和运行编号的报告；未执行或失败的检查不能视作通过。截图仅为辅助证据，不代表完整 GUI 交互验收。实体 Mac 的首次安装、Gatekeeper、局域网权限提示、真实账号调用、Finder/菜单栏交互、系统睡眠与唤醒仍需人工验收。测试产物不属于正式发行，不执行 R2 发布或清理。
