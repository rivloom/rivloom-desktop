# ADR-0003：设备信任与 AI 审批分层

## 状态

已接受。产品负责人于 2026-09-01 明确：完成双向配对的设备已经建立业务信任，受信设备发来的任务不应再次要求逐任务接受；AI 在执行电脑上的文件和命令权限由另一套本机审批策略管理。

## 决策

1. 只有完成双向指纹确认、仍未撤销且加密通道有效的节点可以发送任务。任务通过该边界后，接收节点立即接受，不再提供“每项任务确认”或节点白名单的第二层邀请审批。
2. 本机所有者仍可关闭执行能力、选择专用项目和模型、停止任务或撤销设备信任。关闭能力时已接收的新任务等待，不创建 OpenCode 会话；重新开启后再按本机能力执行。撤销信任会阻止后续消息并停止关联执行。
3. 每项本机任务在创建时锁定一种 AI 审批模式：
   - **请求批准**：读取普通项目文件和搜索自动允许；修改、命令和联网工具请求指定审批人决定。
   - **帮我批准**：项目内修改和命令自动允许；联网工具仍请求批准。
   - **允许任何操作**：受支持的文件、命令和联网工具自动允许，并允许访问项目外目录。它必须显式选择并显示高风险警告。
4. 三种模式都继续拒绝读取 `.env`、私钥、OpenCode 认证文件等敏感内容，也继续禁用子代理和技能加载。这里的“允许任何操作”只表示 Rivloom 当前开放的文件、命令、联网与目录范围，不取消凭据保护或引擎边界。
5. 权限通过 OpenCode 1.18.25 官方 `session.create({ permission })` 规则传入。Rivloom 不修改 OpenCode，不实现工具执行器，也不模拟 Agent 循环。
6. 任务的审批模式创建后保持不变；修改节点默认策略只影响以后收到的跨节点任务。已有任务和会话不会被静默扩大权限。
7. 升级旧配置时，原“自动调用”保留开启但改用“请求批准”；原“有限调用”和“每项确认”关闭执行能力，要求本机所有者按新语义重新开启，避免升级时静默扩大设备或模型调用范围。

## 产品含义

- “信任设备”回答谁可以把任务交给本机。
- “开启执行能力”回答本机是否愿意接活，以及使用哪个本地项目和模型。
- “AI 审批模式”回答 OpenCode 执行过程中哪些动作需要人批准。

三者不能再合并成一个“自动/有限/每项确认”的调用下拉框。若用户不再信任另一台设备，应撤销设备信任；若只想暂停接活，应关闭本机执行能力；若想调整 AI 自主程度，应选择审批模式。

## 当前范围

本决策先落地受信任务自动接收、审批模式持久化和本机会话权限。跨设备展示及处理具体审批请求、AI 提问、补充要求、停止、结果和验收仍属于 M3.3 后续切片。
