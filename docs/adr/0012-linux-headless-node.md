# ADR 0012：Linux 无界面常驻执行节点

## 状态

Linux x64 0.1.18 已发布，同提交原生 CI、公开完整下载与 curl / wget 原生命令验收通过；见 [Linux 0.1.18 发行说明](../releases/linux-0.1.18.md)。[官网下载页](https://rivloom.com/download/) 及配套中英文指南已实际上线并复核。ARM64 保留实现，等待原生架构验收后单独发布；Windows 安装包与签名更新指针保持不变。

## 背景

局域网 Linux 设备通常没有 GUI，由桌面端派发工作，经 SSH 配置和运维。目标覆盖 x86_64 与 ARM64、自包含下载包、GitHub 构建和官网 curl/wget 下载。首次发行按已获授权的范围仅开放 x86_64；ARM64 在完成对应验收前不展示可用下载。

## 决定

复用现有 Node/OpenCode 后端、设备协议、队列和成果传输。新增 `rivloom` CLI，不引入终端聊天 UI 或 Tauri/Linux 图形依赖。命令通过当前用户私有控制文件认证到 loopback HTTP；LAN 仍只使用现有签名发现、双向确认配对与加密信道，CLI 不提供免确认配对。

Linux 数据根属于运行服务的用户，目录权限 0700、身份/凭据文件 0600；Ed25519 私钥依靠系统文件权限保护，**没有声称 Linux 文件具有 DPAPI 式静态加密**。发现无效、权限过宽或平台不匹配的身份时拒绝启动节点网络，不重新生成已有身份。Windows 继续使用 DPAPI。应使用独立非 root 用户；同一账户可读取此账户的任务和密钥，这是既定的本机信任边界。

固定 Node 24.19.0 / OpenCode 1.18.25。首发 Linux x64 使用官方 baseline 二进制，运行基线为内核 4.18、glibc 2.28 和 libstdc++ 6.0.25（`GLIBCXX_3.4.25`）或更新版本；固定 OpenCode 二进制的 glibc 依赖不高于该门槛。ARM64 适配使用对应官方包，暂不纳入首发；不承诺 Alpine/musl、32 位或 macOS。引擎单独创建进程组，退出停止其拥有的子进程。默认执行策略关闭，用户选择项目、模型与审批级别后显式开启。

Linux 的构建代码按架构产出不可变 tar.gz 与 SHA256 校验记录，正式发布范围独立控制。首发只发布通过门槛的 x64 产物；ARM64 没有通过对应原生验收前不提升其公开记录。官网只有真实有效且处于发布范围内的完整记录才开放下载。其记录与 Windows 桌面签名 updater 清单分离，SHA256 完整性校验不称为数字签名或自动更新。用户在停止节点后手动更换程序目录，保留数据目录。当前 Linux 下载入口的文件必须加入 R2 保留并集。

## 取舍

- 后端与桌面功能保持一致，不维护第二套调度/执行协议。
- Linux 用户文件保护无需桌面 keyring，适合无人值守；存储保密依赖主机账户和磁盘保护。
- 自包含包较大，但设备无需预装 Node/npm 或联网安装运行依赖。
- systemd 用户服务由 CLI 输出单元及明确操作说明；不自动修改系统防火墙、提升 root 权限或开启 linger。
- GitHub 原生架构检查与真实 Linux/桌面跨机验收分别记录；x64 首发通过不意味着 ARM64 已验证，不把 Windows 测试或 WSL 单机测试等同于 ARM64 实机验收。

## 备选

完整 TUI 超出执行节点需要；Linux GUI 包不适合目标设备；独立重写 daemon 会重复已有信任、队列及任务逻辑。
