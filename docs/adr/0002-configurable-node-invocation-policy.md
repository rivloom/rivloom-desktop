# ADR-0002：节点能力按策略自动调用

## 状态

已接受并完成第一实施切片。产品方向由用户于 2026-09-01 明确修正；自动/有限/每项确认策略、真实本机 OpenCode 调用和有序状态回传已经通过实际 Release WebView2 验证。

## 产品意图

Rivloom 节点之间的核心体验应是协同做事。受信节点或 Brain 可以自动调用另一节点已开放的执行能力，也可以由能力提供者设置限制；不应要求接受方在每个任务到达后都重新接受邀请、选择项目和模型，再等待发起方启动。

产品提供至少三种可选调用策略：

- **自动调用（目标默认体验）**：任务满足本机预先开放的能力范围时，自动选择已配置的项目和模型并开始执行。
- **有限调用**：按受信节点或 Brain、项目范围、模型配置、并发、额度、时段、工具权限和审批规则限制自动执行。
- **每次确认**：高风险或未匹配既有规则的任务由本机用户逐次确认，也可作为用户主动选择的保守模式。

自动发现仍不等于自动调用。新设备必须先完成信任建立；执行节点只在本机保存项目路径和凭据，并通过本机策略决定可用资源。发起方获得完成协作所需的能力名称、状态、限制和执行结果，不获得本机绝对路径或密钥。

## 对现有实现的影响

原“接受邀请 → 本机临时选择项目与模型 → 创建 30 分钟准备租约”切片是已验证但已否决的技术原型。当前界面已删除该流程；既有 JSON 记录迁移为不可自动执行的历史记录，避免升级后意外启动旧任务。

当前实现以本机持久能力配置匹配远端任务，并把每个远端任务唯一绑定到一个本机业务任务。自动模式匹配后直接创建官方 OpenCode 会话；有限模式只接受配置中的受信节点；每项确认模式才显示人工确认。归属 Brain 只收到单调执行状态和摘要。内部使用全局任务 ID、幂等键、唯一绑定和项目锁防止重复启动，没有暴露租约或 30 分钟等待。

## 下一切片

1. 已把本机项目和模型保存成可复用能力配置，不在每项任务到达后重复选择。
2. 已实现自动、有限、每项确认三种调用策略；界面默认自动调用。
3. 已实现策略匹配、唯一业务任务绑定、真实 OpenCode 启动、重启安全恢复和同项目/并发保护。
4. 已实现单调状态和最终摘要回传；本机路径、模型、本机任务 ID 与凭据不进入节点消息。
5. 已删除准备租约界面并安全迁移旧记录。

下一切片实现跨设备人员角色、审批/回答/补充/停止控制和差异/产物/验收；这些能力不能仅用状态摘要代替。

## 暂不决定

- 自动模式首次启用时采用何种确认文案。
- 发起方默认能看到模型的具体标识，还是只看到用户批准的能力名称。
- 有限调用第一版包含哪些额度、工具和时段字段。

这些属于下一切片的交互和安全细节，不能反过来改变“自动调用是默认目标、限制是可配置选项”的产品方向。
