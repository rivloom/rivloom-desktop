# ADR-0002：节点能力按策略自动调用

## 状态

部分被 [ADR-0003](0003-trust-and-ai-approval.md) 取代。可复用本机项目/模型、真实 OpenCode 调用和有序状态回传继续保留；“有限调用”和“每项任务确认”不再作为设备信任后的第二层邀请审批。

## 产品意图

Rivloom 节点之间的核心体验应是协同做事。受信节点或 Brain 可以自动调用另一节点已开放的执行能力，也可以由能力提供者设置限制；不应要求接受方在每个任务到达后都重新接受邀请、选择项目和模型，再等待发起方启动。

建立设备信任后，任务默认自动选择本机预先开放的项目和模型并开始执行。AI 的文件、命令和联网审批另由“请求批准 / 帮我批准 / 允许任何操作”控制。

自动发现仍不等于自动调用。新设备必须先完成信任建立；执行节点只在本机保存项目路径和凭据，并通过本机策略决定可用资源。发起方获得完成协作所需的能力名称、状态、限制和执行结果，不获得本机绝对路径或密钥。

## 对现有实现的影响

原“接受邀请 → 本机临时选择项目与模型 → 创建 30 分钟准备租约”切片是已验证但已否决的技术原型。当前界面已删除该流程；既有 JSON 记录迁移为不可自动执行的历史记录，避免升级后意外启动旧任务。

当前实现以本机持久能力配置匹配远端任务，并把每个远端任务唯一绑定到一个本机业务任务。归属 Brain 只收到单调执行状态和摘要。内部使用全局任务 ID、幂等键、唯一绑定和项目锁防止重复启动，没有暴露租约或 30 分钟等待。

## 已完成的实现

1. 已把本机项目和模型保存成可复用能力配置，不在每项任务到达后重复选择。
2. 已按 [ADR-0003](0003-trust-and-ai-approval.md) 将调用策略改为设备信任、执行能力开关和 AI 审批模式三层。受信任务自动接收；AI 审批支持请求批准、帮我批准和允许任何操作。
3. 已实现策略匹配、唯一业务任务绑定、真实 OpenCode 启动、重启安全恢复和同项目/并发保护。
4. 已实现单调状态和最终摘要回传；本机路径、模型、本机任务 ID 与凭据不进入节点消息。
5. 已删除准备租约界面并安全迁移旧记录。

审批、回答、补充、停止、官方差异和验收控制已经实现；下一步用物理双机明确跨设备人员角色并验收完整交互。这些能力不能仅用状态摘要或前端视角切换代替。

## 后续边界

- 发起方默认能看到模型的具体标识，还是只看到用户批准的能力名称。
- 若以后增加额度、工具或时段限制，应作为本机执行能力策略扩展，不能重新变成逐任务邀请审批。

这些属于后续交互和安全细节，不能反过来改变“受信任务自动接收、AI 操作由本机会话审批”的产品方向。
