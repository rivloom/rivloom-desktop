# ADR-0007：待办、连接诊断与任务文件交付

## 状态

2026-09-06，用户已授权开发待办通知、连接诊断、附件与成果回传，统一真机验收后续进行。本 ADR 已在当前源码实施，并完成逻辑、协议和隔离完整服务检查；尚未发布，也不代表真机验收通过。实施计划见 [开发计划](../plans/2026-09-06-attention-diagnostics-task-files.md)。

## 背景

现有会话、审批、队列、认证回执与恢复已经形成闭环，但用户需逐个会话查看人工等待，连接故障缺少集中解释，跨机任务只能交换文字和官方差异。本轮之前尚无完整文件传送，不能从差异或执行成功推断成果已回到发起机。

## 决策

1. **待办是现有任务的视图。** 按操作者角色、当前 Execution 与原会话 ID 派生待审批、待回答、待验收和故障。通知去重、免打扰和阅读状态不改变业务状态，点击通知只打开任务。
2. **诊断只陈述可观测事实。** 发现、身份、信任、通道、能力、执行准入与任务阻塞分开检查；未知保持未知，恢复操作复用已有机制，不删除配对、重建身份或自动修改防火墙。
3. **文件随原任务走。** 上传必须由本机操作者选择，描述符随 Task 持久保存，字节不进入广播、任务摘要或 OpenCode 凭据目录。local、指定 Node 和 Brain 调度使用原所有权/中转关系；新增 `task-files-v1` 协商，旧节点文字任务继续兼容。
4. **文件传输与执行分别确认。** 分块传输拥有独立进度、校验和重试；最终字节数/哈希验证前不视为已收到，输入未完整前原任务等待、不创建活动 session。断线继续原传输，不能换一个 Task 掩盖失败。
5. **明确选择与最小落盘。** 不同步项目、不扫描或快照整个目录，不自动解压/执行附件。输入仅写入项目内新建的任务专属目录；拒绝路径逃逸和已有不同内容覆盖。成果由执行端用户选择后沿原任务返回，接收方明确保存。文件哈希仅证明传输一致，不证明内容安全或任务验收通过。
6. **有界资源与权限。** 初版每文件 20 MiB、输入 10 个/总计 50 MiB、持久文件总配额 512 MiB；32 KiB 数据块。每次块请求校验当前信任、原任务与方向，越权/冲突/损坏均保留原因而不自动执行。文件名与媒体格式校验、凭据文件名拦截、受控存储与输出路径检查分别实施。

## 后果与取舍

复用现有通道避免新增公开端口、云存储凭据和另一套设备身份；同一端口的 `/v1/channel/file` 使用独立的受限请求额度，仍复用原加密会话与串行通道；每批最多四个数据块后让出发送机会，使审批与目录同步可继续进行。代价是首次大文件传输需要时间，Brain 任务的 Master 需要中转磁盘空间，配额满时用户需处理后才能继续。

不采用附件直接塞入任务 JSON：其大小会超过现有协议限制并放大重试。也不采用对等机器任意路径读取或自动同步工作区：超出用户授权的文件选择范围，且破坏普通文件夹边界。初版不做压缩包自动解包、项目同步、独立传输服务或无人值守上传。

Windows 通知使用本产品身份与精确原生调用权限；系统通知设置可能阻止显示。未安装预览的通知 API 成功不代表正式安装体验通过，显示/点击回到任务留到统一真机验收。
