# ADR 0017：macOS 引擎命令使用已登记的独立进程组

- 日期：2026-10-22
- 状态：设计已采纳，原生实现与验收进行中；尚不代表 Mac 预览版可发布。

## 问题与约束

Mac ARM64 引擎需要执行 Git、shell 等短命令，也要能取消仍有子孙进程的长任务。固定 Runtime 的中央进程适配器在非 Windows 平台默认请求 `detached`；所固定的 Bun 将该请求传给 macOS 的 `POSIX_SPAWN_SETSID`。这些正常命令因此会离开原引擎 session，原先只接受一个固定 session 的监管边界会拒绝它们。参见 [Bun 1.3.14 的 detached 设置](https://github.com/oven-sh/bun/blob/bun-v1.3.14/src/runtime/api/bun/process.zig#L1288) 和 [macOS spawn 实现](https://github.com/oven-sh/bun/blob/bun-v1.3.14/src/runtime/api/bun/spawn.zig#L337)。

取消不能误杀其他任务或用户进程。PID、PGID、父子关系和进程名本身都不足以成为持久的信号授权；进程退出后号码可能重用。正常退出必须有实际进程退出证据，不能只凭收到取消请求、根进程退出或发送信号成功。新路径还必须保留命令的 stdin、stdout、stderr、额外描述符、环境和退出码语义，并继续支持宿主异常退出后的清理。

## 决策

### 仅对 Mac 构建应用精确源码覆盖

Mac ARM64 的构建在固定 Runtime 提交上应用经过逐文件摘要核对的中央 spawn 适配器覆盖。覆盖自身及其目标文件的前后摘要进入构建输入与来源记录；不把有覆盖的源码描述成未经修改的固定提交。Windows、Linux 保留各自既有 source lock 和构建路径。

宿主通过两个保留的环境变量启用 Mac 适配器。缺失一半配置必须拒绝执行；宿主提供的两项都不存在时保留独立 Runtime 的原有路径。启用后的普通命令通过原生 helper 启动，追加私有取消描述符，不改写调用方已有描述符的编号。shell 命令先转换为实际 shell 及参数，helper 本身不被外层 shell 包裹。目标执行前关闭内部控制连接并移除这两个保留变量。

所有已接管命令的取消入口都使用其私有控制描述符。支持 TERM、KILL 和控制连接 EOF；不支持的信号明确报错，不退回外部 PID 或负 PGID 信号。中央适配器之外的 PTY、插件自建进程等路径不能因这项覆盖而自动获得相同保证。

### 原生身份登记后才创建独立 session

JavaScript 宿主建立专用 `0700` 短目录，原生监管器在其中建立 `0600` 本地 socket。监管器通过内核提供的 peer PID 和凭据确认连接身份，再核对同一用户、实际出生时间、引擎根进程的直接父子关系、原 group/session 和 helper 可执行文件身份。客户端自行声明的 PID、名称或路径不构成授权。macOS 提供相关本地 socket 选项，见 [Apple XNU 的本地 socket 接口](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/sys/un.h)。

启动顺序如下：

1. helper 先作为引擎的普通子进程连接原生监管器。
2. 监管器分配登记编号，经私有状态管道通知 JavaScript 宿主；宿主冻结实际身份并确认。
3. helper 才建立自己的 session，创建同组 watchdog，fork 仍被执行门阻塞的目标，并返回身份回执。原生监管器先核验这些活体身份，再确认核验完成；提前到达的取消请求保留执行门，并等待这次核验完成后清理，监管器断连则立即清理。
4. 宿主重新观察并核验这组实际进程，再打开执行门。

登记到打开执行门之间串行处理，并与周期性观察协调，避免把合法的 session 转换竞态当成未登记逃逸。任何身份、顺序或执行门验证失败都不允许目标运行。未经授权的连接只被拒绝；已经登记的生命周期发生矛盾时，整个宿主进入失败状态。

### 活着的组内成员负责向自身组发送信号

每个命令的 helper 保持为该 session 的存活 leader，持有监管器连接和独立的取消控制。取消、原引擎退出或私有连接 EOF 触发本组 TERM，仍未结束时升级为本组 KILL。信号只通过 `kill(0, ...)` 作用于执行信号的 helper 当前所在组；不接受外部传入的 PID/PGID 作为信号目标。各命令组独立取消。

原引擎 session 和每个命令 session 都有各自的同组 watchdog。只有对应 leader 持有其生命周期管道的写端，所有目标和其他子进程必须关闭该写端。leader 被异常终止时，watchdog 从 EOF 得知故障，核对自己仍在最初的 group/session/UID 中后向自身组 TERM，再按期限 KILL。watchdog 自身存活使该组的号码仍有实际成员持有，故不需要向缓存的外部 PGID 发送信号。

正常完成时，监管器仅在根进程和工作成员都已停止后通知 watchdog 正常退出。控制成员通过私有回执冻结身份，不能按进程名排除。最终成功仍要求 leader、watchdog、登记的命令组及已记录的子孙进程全部实际退出。

### 无法证明时保留失败

进程出生时间缺失或变化、UID 变化、未登记的 group/session 变化、记录上限、查询失败、回执矛盾及期限耗尽均保留失败状态，不因有关进程随后消失而抹掉证据缺口。监管器异常死亡即使由 watchdog 完成清理，宿主也报告异常，不伪造正常关闭回执。诊断只输出有界的固定状态和原因，不输出命令、环境、账号或凭据。

## 取舍与范围

与关闭 `detached` 相比，此方案保留各命令的独立取消边界；与按名称、同 UID 或扫描到的 PID 追杀相比，它把发信号权限留在仍存活的组内原生进程中。代价是每个已接管命令多一个原生 helper、一个 watchdog，以及登记和执行门握手；引擎 session 还多一个 watchdog。构建输入、私有协议、启动延迟和异常收尾都需要维护。

本机制是进程生命周期监管，不是操作系统沙箱，也不承诺任意恶意程序无法自行 daemonize 或逃逸。已观察到的未登记逃逸必须拒绝并保留失败；未覆盖路径不能用普通命令的验收结果代替。权限提升、其他用户进程、真实用户项目、已安装应用和系统进程均不成为清理目标。

## 验收要求

原生验收必须使用实际 helper、shell 和子孙进程，至少覆盖：

- 普通命令及持续短命令启动；stdin、额外描述符、环境隔离和非零退出码。
- 两个同时运行的命令，只取消其中一个；TERM-resistant 子孙最终退出。
- TERM、KILL、取消描述符 EOF，以及引擎根进程、JavaScript 宿主、原生监管器分别异常退出。
- 真 helper 的错误父进程、无效登记或执行门不得运行目标；未登记逃逸仍失败。
- 出生时间变化、旧登记和 PID/PGID 重用不产生新授权；私有控制描述符不传给目标。
- 实际源引擎启动、模型查询、任务执行、取消、重启，以及最终安装包的完整生命周期。

截至本 ADR 创建，设计审查与本地静态检查不能替代上述 Mac 原生结果；此文档不声明这些验收已经完成，也不声明发布、下载或更新流程已经通过。
