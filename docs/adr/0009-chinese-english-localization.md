# ADR-0009：中文与英文界面

日期：2026-09-07。状态：已实现；本地交付与官网发布各自记录。

客户端使用 i18next / react-i18next，语言仅为 `zh-CN` 与 `en`，默认和未知语言回退为简体中文。`shared/locales/zh-CN.json` 与 `en.json` 使用中文源文案作为稳定 key，插值使用 `{{name}}`；React 负责文本转义。启动前完成初始化，语言变化订阅只触发现有组件重新渲染，保留草稿、附件选择、当前会话和 Node 身份。日期采用当前界面 locale，协议枚举、排序身份和请求幂等标识不随语言改变。

桌面语言通过只允许主窗口自有 loopback origin 调用的 `set_desktop_language` 命令写入数据目录 `ui-language.txt`。仅接受两种明确值，使用临时文件和 rename 写入；启动时先读取，避免随机本机端口令浏览器存储失效。内部 Web 调试使用独立的 `rivloom.ui.language` localStorage。原生窗口标题、退出确认、目录/成果选择和通知文字读取同一英文目录；设置保存失败时保留原语言并显示错误。

服务与节点协议继续使用原始值，不接收 UI 语言作为全局服务状态。`systemText` 仅用于应用自有错误和状态字段，以精确目录 key 或固定模板翻译，未知内容原样显示。模板参数不递归翻译。用户输入、AI 回复、工具输出、文件内容、文件名、项目和设备名称、用户填写的拒绝原因均原样保留。历史模型摘要的来源不明确时保留原文，避免把模型输出误当成应用文案。

新增或修改文案时同时维护语言目录，运行 `npm run check:i18n`。该检查在 build 中执行，验证中英文 key/插值一致、React 与相关共享显示模块中的中文源文案、应用错误目录及 Rust 原生文案覆盖。测试同时约束语言动态切换、外部内容保留、原生命令权限和持久化行为。新增语言需要明确更新支持列表、目录、原生白名单及界面选项。

独立 Astro 官网使用内置 i18n 路由与 `getRelativeLocaleUrl`，原中文路径保留，英文使用 `/en/`。页面模板共享，内容目录独立；导航保留语言，语言链接对应当前页面，构建同时输出 `lang`、canonical、hreflang 和 sitemap。下载资格、签名说明和公开发行来源仍由原发行契约验证；本地新客户端不被自动标记为官网下载版本。

官网的本地构建与 Git/Pages 发布是独立结果。多语言源码尚未发布时不能宣称英文网址已上线；桌面安装器也不因构建成功而视为通过真实安装、通知点击或双物理机验收。
